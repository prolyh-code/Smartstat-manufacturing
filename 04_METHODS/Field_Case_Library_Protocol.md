# 실제 가전 조립 현장 Case Library 수집 프로토콜

기획서 §32 "제조 현장 Case Library"와 헌장 G7("실제 가전 제품 조립 현장에서 실제 필요로 하는 것과 실제 적용 사례를 조사")을 실행하기 위한 1차 현장조사 절차입니다. 이 문서는 P0 헌장의 하위 실행 프로토콜이며, 문헌 근거(SRC-109, SRC-110)로 도메인 방향성을, 요구공학(要求工學, Requirements Engineering) 인터뷰 기법 문헌(SRC-111, SRC-112)으로 인터뷰 설계 방법을 보강했다. 실행 방식은 **Ian 본인과 Claude의 1:1 인터뷰**(Claude가 질문, Ian이 본인의 실무 경험을 답변)로 확정되었으며, 본 세션부터 실행에 착수한다.

## 목적

문헌만으로는 알 수 없는, **국내 중소형 가전사 조립라인에서 실제로 발생하는** CTQ·통계적 판단 니즈·현재 대응 방식을 수집하여 Analysis Navigator 시나리오, MVP 우선순위, Case Library 콘텐츠의 근거로 삼는다.

## 인터뷰 기법 근거 및 원칙 (신규, 2026-09-09)

요구공학 분야의 인터뷰 기반 요구사항 도출(requirements elicitation) 연구(SRC-111, SRC-112)에 따르면, 암묵지(暗默知, tacit knowledge) — 응답자가 당연하게 여겨 스스로 언어화하지 않는 지식 — 를 끌어내는 인터뷰는 다음 원칙을 따를 때 더 효과적이다:

1. **추상적 질문보다 구체적 사건(critical incident) 질문이 낫다.** "어떤 통계가 필요하십니까?"보다 "최근에 이 값이 정상인지 판단하기 애매했던 구체적 사례가 있었습니까?"가 더 풍부한 답을 이끈다.
2. **모호한 답변에는 반드시 후속 질문(follow-up probe)으로 구체화한다.** 초보 인터뷰어의 흔한 실패는 후속 질문 부족이다(SRC-111). 본 인터뷰에서는 애매한 답변에 "구체적으로 어떤 수치였습니까?", "그때 어떻게 결론을 내리셨습니까?"로 최소 1회 이상 파고든다.
3. **사다리기법(laddering)**: 표면적 요구("이 기능이 있으면 좋겠다")에서 멈추지 않고 "왜 그것이 필요하십니까?"를 반복해 근본 니즈까지 내려간다.
4. **응답자의 어휘를 그대로 따라간다.** 통계 용어를 먼저 쓰지 않고, Ian이 실제 현장에서 쓰는 표현(예: "튐값", "공정능력 나쁘다" 등)을 그대로 기록한 뒤 필요시에만 통계 용어로 매핑한다.
5. **한 번에 하나씩, 열린 질문으로 시작해 점점 구체화한다.** 제품군 전체 → 특정 공정 → 특정 사례 순으로 좁혀간다.

## 대상 공정 예시 (기획서 §1 제품군 기준)

| 제품군 | 예시 조립/검사 공정 | 예상 CTQ 후보 |
|---|---|---|
| 냉장고 | 도어/가스킷 조립, 단열재 발포, 컴프레서 체결 | 도어 갭, 단열두께, 진동/소음, 냉매 압력 |
| 세탁기 | 모터·베어링 체결, 드럼 밸런싱, 배수호스 결합 | 진동값, 체결토크, 소음, 누수 |
| 에어컨 | 냉매 충전, 리크테스트, 실외기 배관 용접 | 냉매량, 리크율, 배관 압력 |
| 조리기기 | 히터/PCB 조립, 절연저항 검사 | 절연저항, 히터 저항값, 온도편차 |

(실제 사내 공정 목록으로 조사 전 교체·구체화할 것 — 위는 기획서 기반 가설적 예시임)

## 조사 방법 (확정, 2026-09-09)

Ian 본인이 담당 회사의 품질·공정 엔지니어이므로, 외부 인터뷰이 섭외 없이 **Claude와 Ian의 1:1 대화형 인터뷰**로 실행한다. 회당 세션에서 6~10개 질문을 진행하며, 답변이 짧거나 모호하면 즉시 후속 질문으로 구체화한다(위 원칙 2). 인터뷰 결과는 매 세션 종료 후 Case 기록 템플릿에 정리해 워크스페이스에 반영한다.

## 인터뷰 질문 가이드 (확정판 — critical incident + laddering 적용)

**Round 1 — 전체 지형 파악(warm-up, 넓게)**

1. 현재(또는 최근) 담당하신 제품군·공정 범위는 어떻게 되십니까? (냉장고/세탁기/에어컨/조리기기 중 주로 어떤 라인)
2. 그 공정에서 정기적으로 측정·기록하는 값(CTQ) 중 가장 먼저 떠오르는 것 2~3가지는 무엇입니까?

**Round 2 — 구체적 사건 중심(critical incident)**

3. 최근 1년 내, "이 수치가 진짜 달라진 건지 그냥 우연한 변동인지" 판단하기 애매했던 구체적인 사례를 하나만 떠올려 주실 수 있습니까? (언제, 어떤 값, 무엇 때문에 애매했는지)
4. 그 상황에서 실제로 어떻게 결론을 내리셨습니까? (엑셀로 평균 비교 / 감으로 판단 / SPC 관리도 / 그냥 보류 등)
5. 두 라인·설비·작업자·공급업체(또는 변경 전후) 간 차이를 비교해야 했던 최근 경험이 있다면 무엇이었습니까? 어떻게 결론 내리셨습니까?

**Round 3 — 미해결 니즈 파고들기(laddering)**

6. 통계 분석이 필요하다고 느꼈지만 실제로 하지 못했던 경우가 있다면, 왜 못 하셨습니까? (몰라서 / 도구가 없어서 / 시간이 없어서 / 데이터가 없어서 등) — "왜 그게 문제였습니까?"로 한 번 더 파고들기.
7. 그 순간 만약 몇 초 안에 "이건 우연이 아니라 실제 차이입니다"라는 답을 받을 수 있었다면, 다음 행동이 어떻게 달라졌을 것 같습니까?

**Round 4 — 커뮤니케이션·현장판단**

8. 분석 결과를 상사·타부서에 보고할 때 어떤 형태(그래프/숫자/문장)로 설명해야 가장 잘 이해되십니까? 반대로 오해를 산 경험이 있다면?
9. "통계적으로는 차이가 있다"는 결과가 나왔지만 "현장에서는 별 의미 없다"고 판단했던 경험이 있습니까? 그 반대(통계는 애매한데 현장에서는 중요했던 경우)는요?

**Round 5 — 제품군별 구체화(필요 시, 라운드 2~3와 연결해 자연스럽게)**

10. (담당 제품군에 한해) 아래 중 실제로 다뤄보신 공정/이슈가 있다면 편하신 것부터 말씀해 주십시오 — 냉장고: 도어·가스킷 조립, 단열재 발포, 컴프레서 체결/진동; 세탁기: 모터·베어링 체결, 드럼 밸런싱, 누수; 에어컨: 냉매 충전량, 리크테스트, 배관 용접; 조리기기: 히터·PCB 조립, 절연저항, 온도편차. (기획서 기반 가설적 예시이므로 실제와 다르면 바로 잡아 주십시오)

## Case 기록 템플릿 (사례당 1행)

| 필드 | 설명 |
|---|---|
| case_id | CASE-001, CASE-002 ... |
| 제품군/공정 | 예: 세탁기 / 모터 체결 |
| CTQ/측정값 | 예: 체결 토크(N·m) |
| 현재 판단 방식 | 예: 엑셀 평균 비교, 육안 |
| 현재 pain point | 예: "우연한 변동인지 판단 어려움" |
| 필요 통계기법 후보 | 예: 2-Sample t-test, 관리도 |
| MVP 기능 매핑 | Phase1 커버 여부 (Y/N, 미커버 시 사유) |
| 출처 | 인터뷰/관찰, 조사일, 익명화된 역할 |

수집된 사례는 `02_EVIDENCE/`(또는 향후 신설할 `Case_Library_Register.csv`)에 축적하고, Claim_Evidence_Matrix의 CLM-09를 `missing`에서 `observed`로 갱신한다.

## 데이터 처리 원칙

- 개인 식별정보(이름 등) 및 민감한 경영정보(원가, 불량률 절대치 등 회사가 민감하다고 분류하는 정보)는 기록하지 않는다.
- 실제 수치가 필요한 경우 상대값·익명화된 범위로 대체하거나, 사내 승인 후에만 원자료를 보관한다.
- 회사 보안·기밀 규정이 본 프로토콜보다 우선한다.

## 완료 기준

- 최소 3개 이상 제품군에서 각 1건 이상, 총 5건 이상의 사례가 수집되면 G7의 1차 완료 기준으로 본다(잠정 — P0 리뷰 시 조정 가능).
- 수집 후 RQ-10, H4, CLM-09, GAP-06 상태를 갱신한다.
