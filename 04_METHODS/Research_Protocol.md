# Research Protocol — SmartStat Manufacturing

## 연구 설계와 근거

혼합 방법(mixed method): (1) 공개 문헌·경쟁도구 스캔(2차자료), (2) 통계 이론 대조 검증(Navigator 로직을 표준 검정 가정과 대조), (3) **실제 가전 조립 현장 1차 조사**(관찰·인터뷰 — 신규, 최우선), (4) 향후 프로토타입 사용성 검증(미착수). 근거강도가 서로 다른 자료를 혼동하지 않도록 Claim-Evidence Matrix에서 `relation`과 `evidence_grade`로 구분한다.

## 모집단, 단위, 범위, 표집

- 모집단: 국내 중소형 가전 제조업(냉장고·세탁기·에어컨·조리기기)의 품질·공정 엔지니어 및 조립라인 담당자.
- 단위: 개별 분석 세션(사용자 관점) / 개별 조립공정 사례(Case Library 관점).
- 표집: 문헌 스캔은 목적표집(purposive, 검색어 기반); 현장조사는 접근 가능한 사내 조립라인 우선, 이후 필요 시 확대.

## 포함·제외·중단 규칙

- 포함: Phase 1 MVP 범위에 해당하는 통계적 판단이 실제로 발생하는 공정.
- 제외: 비제조 산업 사례, Phase 2/3(SPC·Capability·DOE) 전용 사례는 별도 태그로 기록하되 MVP 범위 claim에는 사용하지 않음.
- 중단: 회사 기밀·보안 규정과 충돌하는 데이터는 수집하지 않고 즉시 중단한다.

## 수집 절차와 도구

### 2차 자료(문헌·경쟁도구) 스캔 절차

1. 연구질문(RQ)별 검색어를 정의한다.
2. 검색 결과 중 관련성 있는 상위 결과를 Source_Register에 등록(출처, 접속일, 근거등급 판정 포함).
3. 각 소스의 핵심 주장을 Claim_Evidence_Matrix에 `supports`/`contradicts`/`contextual`로 분류하여 기록한다.
4. 반증·반대 사례를 의도적으로 탐색한다(예: Navigator형 UI의 한계를 지적하는 문헌).

### 1차 현장 조사(신규, 최우선) — Case Library 수집

`Field_Case_Library_Protocol.md` 참조. 요약:

- 대상 공정 예시: 냉장고 도어/가스킷 조립, 세탁기 모터·베어링 체결, 에어컨 냉매 충전·리크테스트, 조리기기 히터·PCB 조립 등.
- 방법: 현장 관찰(가능 시) + 반구조화 인터뷰(품질·공정 담당자).
- 기록 단위: 공정명, CTQ/측정값, 현재 판단 방식(도구·기준), 현재 pain point, 필요 통계기법 후보, MVP 기능 매핑 여부.
- 결과물: `02_EVIDENCE/` 또는 향후 신설되는 Case Library 레지스터에 사례별로 축적.

## 측정 유효성과 데이터 품질 게이트

- 문헌 자료: 동료심사 여부, 발행처 신뢰도, 발행일(최신성)을 evidence_grade에 반영.
- 현장 조사: 실제 CTQ 수치 데이터를 다룰 경우 spc-profile.md의 측정시스템(V0) 유효성 확인을 선행한다. 측정 변동이 지배적이면 공정능력·판단 결론을 보류한다.

## 분석과 삼각검증(triangulation)

문헌 근거(2차)와 현장 조사(1차)가 상충할 경우 1차 현장 근거를 우선하되, 표본 수가 적으므로(사례 수 개) 일반화하지 않고 "관찰된 사례"로만 기록한다. 기획서(SRC-000)의 설계 가정과 실제 현장 니즈가 불일치하는 지점은 Claim_Evidence_Matrix에 `contradicts`로 명시한다.

## 반증사례, 부정적 사례, 부작용

Navigator·해석엔진이 오히려 혼란을 유발하는 사례, 기존 도구가 이미 충분히 잘 해결하고 있는 문제 등은 숨기지 않고 `Limitations_and_Open_Questions.md`와 Claim_Evidence_Matrix에 기록한다.

## 재현성과 출처 추적

모든 웹 소스는 검색어·접속일·URL을 Source_Register에 기록한다. 현장 조사는 조사일·대상 공정·인터뷰이 역할(익명화)·기록자를 남긴다(개인식별정보 미기록).

## 윤리, 보안, 라이선스, 기밀

사내 데이터·현장 정보는 회사 보안 규정을 우선 준수하며, 개인 식별정보와 민감한 경영정보는 기록하지 않는다. 외부 문헌은 출처를 명시한다.

## 변경 관리와 이탈(deviation) 정책

프로토콜 변경 시 `Decision_Log.csv`에 사유를 기록한다. 아웃컴 임계값·수용 기준은 P4(방법 동결) 승인 전에는 확정하지 않는다.
