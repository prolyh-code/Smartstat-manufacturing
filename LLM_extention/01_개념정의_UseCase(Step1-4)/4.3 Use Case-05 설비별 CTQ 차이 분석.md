> **"전체적으로 차이가 있는가?"와 "구체적으로 어느 설비가 다른가?"를 Agent가 서로 다른 질문으로 인식하는 것**

입니다.

# Step 4-3. UC-05 — 설비별 CTQ 차이 분석

## 1. 대표 사용자 질문

> **"설비별 CTQ 차이가 있는지 분석해줘."**

예를 들어 냉장고 조립라인의 체결 Torque 데이터가 다음과 같이 있다고 가정하겠습니다.

```
Machine 1    Torque
Machine 2    Torque
Machine 3    Torque
Machine 4    Torque
Machine 5    Torque
```

사용자는 단순히 "ANOVA를 해달라"고 하지 않았습니다.

사용자가 실제로 알고 싶은 것은 보통 다음 두 가지입니다.

1. **설비별 차이가 존재하는가?**
2. **차이가 있다면 어느 설비가 다른가?**

그리고 제조적으로는 세 번째 질문이 이어집니다.

3. **그 차이가 실제 공정관리상 중요한 수준인가?**

따라서 하나의 질문 안에 최소 3개의 통계적/제조적 질문이 존재합니다.

---

# 2. Intent → Problem Model

Agent는 질문을 다음과 같이 구조화합니다.

```
Problem Type
= MULTI_GROUP_COMPARISON

Response Variable
= CTQ / Torque

Factor
= Machine

Groups
= Machine 1 ~ Machine 5

Objective
= Difference Detection

Data Type
= Continuous

Relationship
= Initially Unknown
```

여기서도 `Relationship = Initially Unknown`이 중요합니다.

설비가 다르다는 사실만으로 데이터가 독립이라고 확정해서는 안 됩니다.

예를 들어 동일 제품을 여러 설비에서 반복 측정했는지, 시간에 따른 반복측정 구조가 있는지 등을 확인할 필요가 있습니다.

---

# 3. Agent의 첫 번째 분석 질문

Agent는 먼저:

> **"이 데이터는 설비별 독립적인 표본인가?"**

를 확인합니다.

그리고 다음 사항을 평가합니다.

```
Machine
 ├─ Sample Size
 ├─ Measurement structure
 ├─ Time
 ├─ Model
 ├─ Shift
 └─ Operator
```

특히 제조 현장에서는 다음과 같은 데이터 구조가 중요합니다.

```
Machine 1 → Model A 중심
Machine 2 → Model B 중심
Machine 3 → Model C 중심
```

이 경우 설비 차이처럼 보이는 현상이 사실은 **Model 차이**일 수 있습니다.

따라서 UC-05는 UC-03에서 도입한 **Confounding Analysis**를 더 중요한 수준으로 확장합니다.

---

# 4. Analysis Plan

정상적인 다중 그룹 데이터라면 Agent는 다음과 같은 계획을 세울 수 있습니다.

```
Analysis Plan

1. Data Quality Assessment
2. Group Structure Assessment
3. Descriptive Statistics by Machine
4. Distribution Assessment
5. Variance Assessment
6. Overall Group Difference Test
7. Post-hoc Analysis
8. Effect Size
9. Manufacturing Significance
10. Confounding Assessment
11. Next Best Analysis
```

여기서 중요한 것이 **7번 Post-hoc**입니다.

---

# 5. 왜 ANOVA만으로는 부족한가

예를 들어 5개 설비의 평균이 다음과 같다고 하겠습니다.

|설비|평균 Torque|
|---|---|
|M1|35.1|
|M2|35.2|
|M3|35.3|
|M4|36.2|
|M5|35.2|

ANOVA 결과:

```
p < 0.001
```

이라면 Agent는:

> 설비 간 평균에 통계적으로 유의한 차이가 존재합니다.

라고 말할 수 있습니다.

하지만 이것만으로는:

> **어느 설비가 다른가?**

를 알 수 없습니다.

즉,

```
ANOVA
= "차이가 있는가?"

Post-hoc
= "어디에서 차이가 나는가?"
```

라는 서로 다른 질문입니다.

---

# 6. ANOVA → Post-hoc의 Agent Logic

Agent는 다음과 같은 흐름으로 판단합니다.

```
3+ Groups
     │
     ▼
Data Structure Check
     │
     ▼
Variance / Distribution
     │
     ├───────────────┐
     ▼               ▼
Homogeneous       Unequal
Variance          Variance
     │               │
     ▼               ▼
One-way ANOVA    Welch ANOVA
     │               │
     └───────┬───────┘
             ▼
      Overall p-value
             │
       ┌─────┴─────┐
       │           │
     p≥α          p<α
       │           │
       ▼           ▼
    Stop       Post-hoc
                   │
                   ▼
            Pairwise Results
```

---

# 7. Post-hoc 선택도 Agent의 책임

여기서 중요한 것은:

> "ANOVA 다음에는 Tukey를 실행한다."

라는 고정 규칙을 만드는 것이 아닙니다.

데이터 조건에 따라 적절한 방법을 선택해야 합니다.

예를 들어:

### 일반적인 조건

분산이 크게 다르지 않고 일반적인 ANOVA 조건을 충족한다면:

> **Tukey**

를 우선 검토할 수 있습니다.

### 분산이 불균등하다면

> **Welch ANOVA + Games-Howell**

을 검토합니다.

### 보수적인 다중비교가 필요하다면

> Bonferroni, Scheffé

등을 고려할 수 있습니다.

따라서 Agent Architecture에서는:

```
PostHocSelector
```

를 별도의 Rule/Decision Tool로 만드는 것이 좋습니다.

---

# 8. Statistical Engine의 역할

예를 들어 Welch ANOVA를 선택했다고 하겠습니다.

Agent는:

```
welch_anova(
    response="Torque",
    factor="Machine"
)
```

을 호출합니다.

Statistical Engine:

```
F = 18.42
df1 = 4
df2 = 271.6
p < 0.001
```

을 반환합니다.

그리고 Agent가:

```
games_howell(
    response="Torque",
    factor="Machine"
)
```

을 호출합니다.

예를 들어 결과가:

|비교|Mean Difference|p-value|유의|
|---|---|---|---|
|M1-M2|-0.1|0.82|No|
|M1-M3|-0.2|0.61|No|
|M1-M4|-1.1|<0.001|Yes|
|M1-M5|-0.1|0.91|No|
|M2-M3|-0.1|0.74|No|
|M2-M4|-1.0|<0.001|Yes|
|M2-M5|0.0|0.99|No|
|M3-M4|-0.9|<0.001|Yes|
|M3-M5|0.1|0.77|No|
|M4-M5|1.0|<0.001|Yes|

와 같이 반환될 수 있습니다.

---

# 9. Agent가 찾아야 하는 핵심 Finding

여기서 Agent는 단순히 모든 Pairwise 결과를 나열해서는 안 됩니다.

분석 결과를 **Finding**으로 압축해야 합니다.

예:

> **Finding F01**  
> 전체 설비 간 CTQ 평균 차이가 통계적으로 유의합니다.  
> Evidence = E2

그리고:

> **Finding F02**  
> M4의 평균 Torque가 M1, M2, M3, M5보다 유의하게 높습니다.  
> Evidence = E2

그리고:

> **Finding F03**  
> M1, M2, M3, M5 사이에서는 통계적으로 유의한 차이가 확인되지 않았습니다.  
> Evidence = E2

이렇게 하면 Agent State에 저장할 수 있습니다.

---

# 10. 여기서 Effect Size가 중요해진다

ANOVA에서는 단순 p-value 외에도 **η² 또는 partial η²** 같은 효과크기를 사용할 수 있습니다.

예:

```
η² = 0.21
```

이라면 Agent는:

> 설비 요인이 CTQ 변동의 일정 부분과 관련되어 있으며, 단순히 표본 수가 커서 통계적으로 유의한 것만으로 보기는 어렵습니다.

라고 해석할 수 있습니다.

다만 **효과크기의 제조적 의미는 공정 특성 및 규격과 함께 판단**해야 합니다.

---

# 11. 제조적 판단

예를 들어:

```
Target = 35.0
USL = 40.0
LSL = 30.0

M1 = 35.1
M2 = 35.2
M3 = 35.3
M4 = 36.2
M5 = 35.2
```

이라면 M4가 다른 설비보다 높다는 사실은 통계적으로 명확합니다.

그러나 M4의 값이 여전히 규격 안에 있을 수 있습니다.

따라서 Agent의 판단은 다음처럼 2단계여야 합니다.

### Statistical Judgment

> M4는 다른 설비보다 평균 Torque가 통계적으로 유의하게 높습니다.

### Manufacturing Judgment

> 현재 평균값은 규격 범위 안에 있지만 다른 설비 대비 중심 위치가 이동해 있습니다. 공정 간 균일성 관점에서 M4의 원인을 확인하는 것이 권장됩니다.

이것이 단순 통계 프로그램과 **Manufacturing Statistical Agent**의 차이를 만드는 부분입니다.

---

# 12. 가장 중요한 부분 — Confounding

이제 Agent가 한 단계 더 들어갑니다.

M4의 Torque가 높다는 것을 발견했는데 데이터를 확인하니:

```
M4
 ├─ Model A : 10%
 ├─ Model B : 10%
 └─ Model C : 80%

Other Machines
 ├─ Model A : 40%
 ├─ Model B : 40%
 └─ Model C : 20%
```

라면 단순히:

> M4가 문제다.

라고 할 수 없습니다.

Agent는 다음과 같이 상태를 업데이트합니다.

```
Finding
= M4 has higher Torque

Evidence
= E2

Potential Confounder
= Model

Confidence
= Limited

Next Analysis
= Compare Machine within same Model
```

---

# 13. Next Best Analysis

이 경우 가장 가치 있는 다음 분석은 단순히 다른 통계 검정을 추가하는 것이 아닙니다.

예를 들어:

```
Model A
 ├─ M1
 ├─ M2
 ├─ M3
 └─ M4

Model B
 ├─ M1
 ├─ M2
 ├─ M3
 └─ M4

Model C
 ├─ M1
 ├─ M2
 ├─ M3
 └─ M4
```

처럼 **동일 Model 조건에서 Machine 효과를 확인**하는 것이 더 중요합니다.

또는 충분한 데이터가 있다면:

```
Torque
 ~ Machine
 + Model
 + Shift
 + Operator
```

와 같은 다변량 모델로 확장할 수도 있습니다.

---

# 14. Agent가 "무엇을 발견했는가"와 "왜 그런가"를 구분

이것은 UC-05에서 반드시 구현해야 할 개념입니다.

### Finding

> M4의 평균 Torque가 다른 설비보다 높다.

### Hypothesis

> M4의 체결 조건 또는 설비 상태가 영향을 미쳤을 가능성이 있다.

둘은 다릅니다.

```
Observed Finding
       ↓
Statistical Evidence
       ↓
Candidate Hypothesis
       ↓
Additional Analysis
       ↓
Experimental Verification
```

따라서 Agent가:

> "M4의 체결 설비가 원인입니다."

라고 말해서는 안 됩니다.

현재 단계에서는:

> **"M4가 높은 Torque와 관련된 주요 후보 설비로 확인되었습니다."**

정도가 적절합니다.

# 15. UC-05의 최종 응답 구조

실제 사용자에게는 지나치게 통계적인 형태보다 다음 구조가 적합합니다.

### 결론

> **설비별 Torque 평균에는 통계적으로 유의한 차이가 있으며, 특히 M4가 다른 설비보다 높은 수준으로 나타났습니다.**

### 핵심 결과

```
전체 설비 비교
→ 유의한 차이 있음

주요 차이
→ M4 > M1
→ M4 > M2
→ M4 > M3
→ M4 > M5
```

### 제조적 의미

> M4의 중심 위치가 다른 설비보다 높아 설비 간 공정 균일성이 확보되지 않은 상태일 가능성이 있습니다.

### 주의사항

> 다만 M4에서 특정 모델의 생산 비중이 높다면 모델 효과가 설비 효과와 혼재될 수 있습니다.

### 추천 다음 분석

> **동일 모델 조건에서 설비별 Torque를 다시 비교하는 것을 권장합니다.**

# 20. 다음 UC-07에서 중요한 변화

다음은 **"개선 전과 후에 품질이 좋아졌는지 확인해줘."**입니다.

여기서는 새로운 문제가 등장합니다.

예를 들어:

> 개선 전 평균 35.8  
> 개선 후 평균 35.1

이라고 해서 바로:

> **개선 효과가 있었다.**

라고 할 수 없습니다.

Agent는 먼저:

- 동일 제품인가?
- 동일 위치를 측정했는가?
- Before/After가 paired인가?
- 시간에 따른 다른 변화는 없는가?
- 표본 수가 충분한가?
- 평균뿐 아니라 변동도 개선됐는가?
- 규격 이탈률도 개선됐는가?
- 통계적으로 유의한가?
- 실제 제조적으로 의미 있는가?

를 판단해야 합니다.

따라서 UC-07에서는 지금까지의 **통계적 유의성 + Effect Size + 제조적 유의성 + 데이터 생성 구조**에 더해,

> **"개선 효과를 어떻게 정의할 것인가?"**

라는 개념을 Agent에 추가하게 됩니다.

그리고 이것이 완료되면 마지막으로 **UC-11 "불량 증가 원인 탐색"**을 설계할 수 있습니다.

UC-11에서는 지금까지 만든 모든 개념이 하나로 결합됩니다.

**Intent → Problem Model → Data Assessment → Analysis Graph → Tool Chain → Finding → Hypothesis → Confounding → Evidence → Next Best Analysis → Stop/DOE → Engineering Decision**

이 단계까지 가면 우리가 처음부터 만들려고 했던 **LLM 기반 제조 통계분석 Agent의 실제 행동 모델**이 거의 완성됩니다.
