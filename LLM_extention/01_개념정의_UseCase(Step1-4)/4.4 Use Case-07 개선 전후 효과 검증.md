좋습니다. 이제 **Step 4-4 — UC-07 「개선 전후 효과 검증」**으로 넘어가겠습니다.

UC-07은 지금까지 만든 Agent의 능력을 한 단계 더 발전시키는 중요한 시나리오입니다. 단순히 "Before와 After의 평균이 다른가?"가 아니라 **"개선 활동이 실제로 효과가 있었다고 판단할 수 있는가?"**를 다루기 때문입니다.

---

# Step 4-4. UC-07 — 개선 전후 효과 검증

## 1. 대표 사용자 질문

> **"개선 전과 후에 품질이 실제로 좋아졌는지 확인해줘."**

제조 현장에서는 매우 흔한 질문입니다.

예를 들어 체결 Torque 개선을 실시했다고 하겠습니다.

- 개선 전: 체결 조건 A
- 개선 후: 체결 조건 B
- CTQ: Torque
- 목표: 평균 편차 감소 및 변동 감소
- 규격: 30~40 N·m

사용자가 원하는 것은 단순한 통계 결과가 아닙니다.

> **"그래서 개선이 성공한 것인가?"**

입니다.

---

# 1.5. 이번 시나리오에서 새롭게 정의해야 할 것

UC-01~05에서는 주로

> **차이가 있는가?**

를 판단했습니다.

UC-07에서는 질문이 바뀝니다.

> **변화가 있었는가? → 그 변화가 개선인가? → 그 개선이 우연이 아닌가? → 제조적으로 의미가 있는가?**

따라서 다음 구조가 필요합니다.

```
Change
  ↓
Statistical Difference
  ↓
Direction
  ↓
Effect Size
  ↓
Manufacturing Significance
  ↓
Improvement Effect
```

이것이 UC-07의 핵심입니다.

---

# 2. Intent → Problem Model

Agent는 질문을 다음과 같이 구조화합니다.

```
Problem Type
= IMPROVEMENT_EFFECT_VERIFICATION

Response Variable
= CTQ

Condition
= Before / After

Objective
= Verify Improvement Effect

Expected Direction
= Depends on Improvement Goal

Data Type
= Continuous

Relationship
= Initially Unknown
```

여기서 **Expected Direction**이 중요합니다.

예를 들어:

### Torque 편차 감소

```
Before SD = 1.20
After SD = 0.70

→ Smaller is better
```

반면:

### FPY 증가

```
Before FPY = 96.2%
After FPY = 98.1%

→ Larger is better
```

따라서 Agent는 단순히 "값이 증가했다/감소했다"가 아니라 **개선 방향(Improvement Direction)**을 알아야 합니다.

---

# 3. 첫 번째 질문: Before/After는 정말 Paired인가?

여기서 UC-03에서 배운 원칙이 다시 등장합니다.

사용자가:

> "개선 전과 후를 비교해줘."

라고 했다고 해서 자동으로 Paired t-test를 선택하면 안 됩니다.

Agent는 데이터 생성 구조를 확인합니다.

---

## Case A — Paired

동일한 대상에 대해 개선 전후를 비교한 경우:

```
Product 001
Before = 35.8
After  = 35.1

Product 002
Before = 36.2
After  = 35.4
```

→ Paired

---

## Case B — Independent

개선 전 생산품 200개와 개선 후 생산품 200개를 별도로 측정:

```
Before
Product 001~200

After
Product 201~400
```

→ Independent

---

## Case C — Time Series / Process Data

개선 전후가 시간축으로 연결되어 있고 장기간 생산 데이터가 존재:

```
Before
──────────────────│
                  ↑ Improvement
                  │
After             ──────────────────
```

이 경우 단순 t-test보다 **시간 변화, 추세, 공정 안정성**을 함께 보는 것이 중요할 수 있습니다.

---

# 4. Agent의 Data Assessment

따라서 다음을 확인합니다.

|항목|확인 내용|
|---|---|
|Before/After 구분|명확한가|
|Pair ID|동일 대상 대응 여부|
|Sample size|충분한가|
|CTQ|동일 측정항목인가|
|Unit|동일한가|
|Measurement method|측정방법 변경 여부|
|Time|개선 시점 명확한가|
|Model|동일 모델인가|
|Machine|동일 설비인가|
|Shift|동일 조건인가|
|Specification|개선 전후 동일한가|
|Missing|결측 수준|
|Outlier|이상값 영향|
|Improvement target|무엇을 개선하려는가|

특히 **측정방법 자체가 개선 전후에 변경되었는지**를 확인해야 합니다.

측정 시스템이 달라졌다면 Before/After 차이가 공정 변화인지 측정시스템 변화인지 구분하기 어려워집니다.

정상적인 데이터라면 Agent는 다음과 같은 계획을 세울 수 있습니다.


# 6. "품질이 좋아졌다"를 무엇으로 정의할 것인가?

이것이 UC-07의 핵심적인 설계 문제입니다.

예를 들어 개선 전후가:

```
Before Mean = 35.8
After Mean  = 35.1
```

이라면 평균은 목표값 35에 가까워졌습니다.

좋은 변화처럼 보입니다.

그런데:

```
Before SD = 0.50
After SD  = 1.20
```

라면 변동이 오히려 커졌습니다.

따라서:

> 평균은 개선되었지만 변동은 악화되었습니다.

가 됩니다.

즉 **Improvement Score는 단일 지표가 아닐 수 있습니다.**

# 7. Agent가 보는 Improvement Dimension

CTQ 개선에서는 최소한 다음 차원을 분리하는 것이 좋습니다.

### ① Centering

목표값에 가까워졌는가?

```
|Mean - Target|
```

### ② Variation

변동이 감소했는가?

```
SD
CV
Range
```

### ③ Specification Compliance

규격 이탈이 감소했는가?

```
Defect Rate
Out-of-Spec Rate
```

### ④ Process Capability

조건이 적절하다면:

```
Cp
Cpk
Pp
Ppk
```

### ⑤ Stability

시간에 따른 공정 안정성이 좋아졌는가?

```
Control Chart
```

따라서 Agent는 사용자의 "품질이 좋아졌는지"라는 질문을 여러 평가축으로 분해할 수 있습니다.

---

# 8. Statistical Test Selection

예를 들어 동일 제품의 Before/After라면:

```
Paired Structure
      ↓
Difference = After - Before
      ↓
Paired t-test
```

를 검토합니다.

독립표본이면:

```
Independent
      ↓
Two Sample Comparison
      ↓
t-test / Welch
```

를 검토합니다.

그리고 데이터 조건에 따라:

```
Non-normal / paired
→ Wilcoxon Signed-Rank

Non-normal / independent
→ Mann-Whitney U
```

등으로 전환할 수 있습니다.

이 부분 역시 LLM이 결정하는 것이 아니라 **Rule Engine + Analysis Planner**가 담당합니다.

---

# 9. Paired Analysis의 핵심

Paired 데이터에서는 단순히 Before 평균과 After 평균을 비교하는 것보다 **개별 차이값**을 분석하는 것이 핵심입니다.

```
Difference_i = After_i - Before_i
```

예:

|Product|Before|After|Difference|
|---|---|---|---|
|1|35.8|35.2|-0.6|
|2|36.1|35.4|-0.7|
|3|35.5|35.1|-0.4|
|...|...|...|...|

Agent는 이 차이의 평균, 분포, 신뢰구간 등을 분석합니다.

---

# 10. Statistical Result

예를 들어:

```
Mean Difference = -0.62
95% CI = [-0.75, -0.49]

t = -8.21
p < 0.001

Effect Size
dz = 0.74
```

라면 Agent는:

> 개선 후 Torque가 평균적으로 0.62 N·m 감소했으며, 차이는 통계적으로 유의합니다. 95% 신뢰구간은 -0.75~-0.49 N·m입니다.

라고 판단합니다.

그러나 아직:

> **개선 성공**

이라고 말하지 않습니다.

---

# 11. Improvement Direction 판단

이제 사용자가 설정한 목표와 비교합니다.

예:

```
Target = 35.0

Before = 35.62
After  = 35.00
```

그러면:

```
Distance to Target

Before = 0.62
After  = 0.00
```

따라서 중심값 관점에서는 명확한 개선입니다.

Agent:

> 평균 Torque가 목표값에 가까워졌으며, 개선 방향과 일치합니다.

라고 판단할 수 있습니다.

---

# 12. 그런데 변동은 어떠한가?

예를 들어:

```
Before SD = 0.85
After SD = 0.82
```

이면 변동도 소폭 감소했습니다.

따라서:

```
Centering     개선
Variation     개선
Mean Difference 유의
```

가 됩니다.

이 경우에는 개선 효과에 대한 근거가 강해집니다.

---

# 13. 반대로 이런 경우는?

```
Before Mean = 35.8
After Mean = 35.1

Before SD = 0.50
After SD = 1.30
```

Agent는 단순히:

> 개선 후 평균이 목표값에 가까워졌습니다.

라고만 하면 안 됩니다.

다음과 같이 판단해야 합니다.

> 평균 중심 위치는 목표값에 가까워졌지만 변동성이 크게 증가했습니다. 따라서 평균 중심 개선만으로 전체적인 공정 개선이 이루어졌다고 판단하기 어렵습니다.

이런 **복합 판단**이 LLM Agent의 중요한 가치입니다.

---

# 14. Specification 관점의 판단

규격이:

```
LSL = 30
USL = 40
```

이라면 평균과 SD만으로 끝내지 않고 규격 성능을 비교할 수 있습니다.

예:

```
Before
Defect Rate = 1.8%

After
Defect Rate = 0.4%
```

이라면 품질 결과 측면에서 상당히 중요한 개선 근거입니다.

따라서 Agent는:

> 평균은 개선되었고, 규격 이탈률도 감소했습니다.

라고 종합할 수 있습니다.

---

# 15. 개선 효과의 Evidence Level

UC-07에서는 Evidence Level이 더욱 중요해집니다.

### E1 — 관찰

> 개선 후 평균이 낮아졌다.

### E2 — 통계적 근거

> Before/After 차이가 통계적으로 유의하다.

### E3 — 복수 지표 및 조건에서 일관된 개선

예:

- 평균 개선
- 변동 감소
- 불량률 감소
- 동일 모델에서도 개선

### E4 — 실제 개선 검증

예:

- 현장 개선 적용
- 반복 생산
- 동일 조건 검증
- 장기간 안정성 확인
- 공정능력 개선
- 실제 불량 감소 확인

따라서 단 한 번의 t-test 결과를 가지고:

> "개선 효과가 검증되었습니다."

라고 말하는 것은 과도할 수 있습니다.

# 17. 최종 응답 예시

사용자에게는 다음과 같은 형태가 적합합니다.

### 결론

> **개선 후 평균 Torque는 목표값에 가까워졌으며 통계적으로 유의한 변화가 확인되었습니다. 변동과 규격 이탈률도 함께 감소하여 현재 데이터에서는 개선 효과를 뒷받침하는 근거가 있습니다.**

### 핵심 결과

|지표|개선 전|개선 후|판단|
|---|---|---|---|
|평균|35.62|35.00|개선|
|SD|0.85|0.72|개선|
|규격 이탈률|1.8%|0.4%|개선|
|평균 차이||-0.62|유의|
|p-value||<0.001|유의|
|Effect Size||0.74|중간~큰 효과|

### 통계적 판단

> Before와 After의 차이는 통계적으로 유의합니다.

### 제조적 판단

> 평균이 목표값에 가까워졌고 변동 및 규격 이탈률도 감소하여 제조 품질 측면에서도 개선 방향이 일치합니다.

### 한계

> 현재 분석은 제공된 Before/After 데이터에 기반한 것이므로 장기간 공정 안정성까지 확인한 것은 아닙니다.

### 권장 다음 단계

> 개선 조건을 일정 기간 유지한 후 SPC 또는 공정능력 분석을 통해 개선 효과의 지속성을 확인하는 것을 권장합니다.

이 마지막 문장이 중요합니다.

**통계분석 → 개선 효과 판단 → SPC를 통한 지속성 검증**

으로 연결되기 때문입니다.

# 19. UC-07에서 중요한 설계 원칙

이번 시나리오에서 다음 원칙을 추가하는 것을 제안합니다.

> ### **Improvement ≠ Statistical Difference**

즉,

```
Statistical Difference
        ≠
Improvement
```

입니다.

더 정확히는:

```
Statistical Difference
       +
Correct Improvement Direction
       +
Practical Significance
       +
Quality/Specification Impact
       +
Sustained Process Performance
       ↓
Improvement Evidence
```

이 구조를 Agent의 **Improvement Judgment Framework**로 발전시키는 것이 좋습니다.

따라서 다음 단계에서는 단순한 Use Case 설명을 넘어, **실제 데이터를 가정하여 UC-11의 전체 대화와 Agent State 변화, Analysis Plan Graph, Tool Call Chain, Finding/Hypothesis/Evidence 생성 과정까지 하나의 완전한 End-to-End Scenario로 설계**하는 것이 적절합니다.

이것을 완성하면 Step 4의 핵심 목표인 **"실제 제조 현장에서 이 Agent가 어떻게 행동해야 하는가"**가 구체적으로 정의됩니다.
