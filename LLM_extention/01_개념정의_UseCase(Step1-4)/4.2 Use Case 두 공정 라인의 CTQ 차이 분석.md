# Step 4-2. UC-03 — 두 공정/라인의 CTQ 차이 분석

### 대표 사용자 질문

> **"A라인과 B라인의 토크 차이가 있는지 확인해줘."**

이 시나리오는 UC-01보다 한 단계 어렵습니다.

단순히 두 평균을 계산하는 것이 아니라 Agent가 **질문의 통계적 구조를 파악하고, 데이터 생성 구조와 가정을 확인한 뒤 적절한 비교 방법을 선택**해야 하기 때문입니다.

---

## 1. User Intent → Problem Model

사용자의 자연어 질문을 Agent가 다음과 같이 구조화합니다.

```
Problem Type
= GROUP_COMPARISON

Response Variable
= Torque

Factor
= Line

Groups
= A, B

Objective
= Difference Detection

Data Type
= Continuous

Relationship
= Initially Unknown
```

여기서 마지막 항목이 중요합니다.

사용자가 "A라인과 B라인"이라고 했다고 해서 Agent가 곧바로 **Independent Two-Sample t-test**를 선택하면 안 됩니다.

먼저 **데이터 생성 구조**를 확인해야 합니다.

---

# 2. Agent의 첫 번째 판단

Agent는 다음 질문을 내부적으로 평가합니다.

> A라인과 B라인의 측정값은 서로 독립적인가?

예를 들어:

### Case A — 독립

```
A라인 생산품 100개
B라인 생산품 100개
```

각 제품이 서로 다른 생산품이라면 일반적으로 독립표본 비교를 검토합니다.

### Case B — 대응

예를 들어 동일한 제품 또는 동일한 시험체를 조건 A/B에서 측정했다면:

```
Product 001
 A = 35.2
 B = 34.8

Product 002
 A = 35.4
 B = 35.0
```

이는 **Paired 구조**일 가능성이 있습니다.

따라서 Agent는 단순히 "두 그룹"이라는 사실만으로 검정을 선택하지 않습니다.

---

# 3. 필요한 Data Assessment

Agent가 확인해야 할 데이터는 다음과 같습니다.

|항목|확인 내용|
|---|---|
|Response|Torque|
|Group|Line|
|Group 수|2|
|Sample Size|A/B 각각의 n|
|Data Type|Continuous|
|Pair ID|대응 여부|
|Missing|결측값|
|Duplicate|중복|
|Unit|N·m 등|
|Time|측정 시점|
|Model|모델 구성 차이|
|Machine|설비 차이|
|Shift|교대조 차이|

특히 **Model**은 제조 현장에서는 상당히 중요한 변수입니다.

---

# 4. 제조 현장의 중요한 함정 — Line 효과와 Model 효과

예를 들어 데이터가 다음과 같다고 하겠습니다.

```
Line A
 ├─ Model 1 : 90%
 └─ Model 2 : 10%

Line B
 ├─ Model 1 : 10%
 └─ Model 2 : 90%
```

그리고 결과가:

```
Line A mean = 35.1
Line B mean = 36.0
p < 0.001
```

이라면 단순하게:

> B라인의 토크가 높다.

라고 말할 수는 있습니다.

그러나:

> **라인 자체가 토크 차이의 원인이다.**

라고 말할 수는 없습니다.

Model 구성이 완전히 다르기 때문입니다.

따라서 UC-03은 단순한 t-test 사례가 아니라 **제조 Agent가 교란요인을 인식하는지 평가하는 좋은 Benchmark**가 됩니다.

---

# 5. Analysis Planner

정상적인 독립 2그룹 데이터라면 Agent는 다음과 같이 계획할 수 있습니다.

```
Analysis Plan

1. Data Quality
2. Group Structure
3. Descriptive Statistics
4. Distribution Assessment
5. Variance Assessment
6. Two-Group Comparison
7. Effect Size
8. Confidence Interval
9. Manufacturing Significance
10. Confounding Check
11. Next Best Analysis
```

여기서 기존 프로그램과 중요한 차이가 생깁니다.

기존 프로그램은:

> "2 Sample t-test"

가 최종 선택일 수 있습니다.

Agent에서는 **분석 계획 전체가 하나의 객체**가 됩니다.

---

# 6. 적절한 통계 방법 선택

Agent의 내부 의사결정 구조는 다음과 같이 설계할 수 있습니다.

```
Two Groups
     │
     ▼
Independent?
 ┌───┴───┐
No      Yes
│        │
Paired   ▼
        Distribution
           │
      ┌────┴────┐
      │         │
  Acceptable  Problematic
      │         │
      ▼         ▼
 Variance    Nonparametric
   Check
      │
 ┌────┴────┐
Equal     Unequal
 │          │
 ▼          ▼
t-test    Welch t-test
```

단, 실제 Rule Engine에서는 단순한 Normality Test 하나만으로 결정하지 않고 **데이터 크기, 분포, 이상값, 목적, 강건성** 등을 함께 고려하도록 설계하는 것이 바람직합니다.

---

# 7. Statistical Engine의 역할

예를 들어 Welch t-test를 선택했다면 LLM이 계산하지 않습니다.

Agent:

```
welch_t_test(
    response="Torque",
    group="Line",
    group_a="A",
    group_b="B"
)
```

Statistical Engine:

```
n_A = 120
n_B = 115

Mean_A = 35.21
Mean_B = 35.74

Mean Difference = -0.53

t = -3.21
df = 198.4
p = 0.0016

95% CI
[-0.86, -0.20]
```

이렇게 구조화된 결과를 반환합니다.

---

# 8. Result Validation

여기서 Agent는 결과를 그대로 사용자에게 전달하지 않습니다.

**Result Guard**가 먼저 확인합니다.

```
Result Validation

✓ test executed
✓ group count = 2
✓ sample sizes valid
✓ statistic available
✓ df available
✓ p-value available
✓ CI available
✓ effect size available
✓ assumptions/warnings checked
```

그리고 Tool 결과와 Analysis State가 일치하는지 확인합니다.

---

# 9. 통계적 판단

Agent는 다음과 같이 해석할 수 있습니다.

> A라인과 B라인의 평균 토크 차이는 통계적으로 유의합니다. B라인의 평균 토크가 A라인보다 약 0.53 높으며, 95% 신뢰구간은 약 0.20~0.86의 차이를 나타냅니다.

하지만 이것으로 끝나면 안 됩니다.

---

# 10. Effect Size를 함께 판단

예를 들어 Cohen's d가:

```
d = 0.42
```

라고 한다면 단순히:

> p < 0.05이므로 차이가 있다.

보다 훨씬 풍부한 판단이 가능합니다.

Agent는:

> 두 라인의 차이는 통계적으로 유의하며, 효과크기 역시 일정 수준의 차이를 나타냅니다.

라고 설명할 수 있습니다.

그리고 제조 기준이 있다면:

```
Mean Difference
vs
Engineering Tolerance
vs
Specification Width
vs
Process Target
```

를 비교해야 합니다.

---

# 11. 제조적 유의성 판단

예를 들어 규격이:

```
Target = 35
LSL = 30
USL = 40
```

이라면:

```
A = 35.21
B = 35.74
Difference = 0.53
```

Agent는 다음과 같이 판단할 수 있습니다.

> 두 라인의 차이는 통계적으로 유의합니다. 다만 평균 차이 0.53이 실제 제품 기능 또는 규격 충족에 의미 있는 수준인지는 별도로 판단해야 합니다.

이렇게 **Statistical Significance와 Manufacturing Significance를 분리**합니다.

---

# 12. Confounding Check

이제 Agentic 기능이 본격적으로 들어갑니다.

Agent가 데이터에서 다음을 발견했다고 가정하겠습니다.

```
Finding F01
Line B has higher Torque
Evidence = E2

Finding F02
Model composition differs substantially
between Line A and Line B
Evidence = E1

Potential Confounder
= Model
```

그러면 Agent는 결론을 낮은 수준으로 조정합니다.

### 잘못된 결론

> B라인이 토크를 높이는 원인이다.

### 적절한 결론

> B라인의 토크가 A라인보다 높다는 통계적 차이가 확인되었습니다. 그러나 두 라인의 모델 구성 차이가 커서 현재 결과만으로 라인 자체의 영향을 확정하기 어렵습니다.

그리고 **Next Best Analysis**를 생성합니다.

---

# 13. Next Best Analysis

가능한 다음 분석은:

### Option 1 — Model별 Line 비교

```
Model 1
 A vs B

Model 2
 A vs B
```

### Option 2 — 동일 Model 데이터만 사용

라인별 동일 모델의 데이터를 추출하여 비교합니다.

### Option 3 — Regression / General Linear Model

```
Torque
 ~ Line + Model + Shift + Machine
```

등으로 확장할 수 있습니다.

여기서 Agent는 모든 것을 무조건 실행하는 것이 아니라 **정보가치가 가장 높은 분석**을 선택해야 합니다.

앞서 정의한:

> **Relevance × Expected Information Gain × Data Availability × Statistical Validity × Manufacturing Impact**

원칙을 적용합니다.

---

# 14. 사용자에게 보여주는 최종 결과 구조

사용자가 통계 전문가가 아니더라도 결과를 이해할 수 있도록 다음 구조가 적합합니다.

### 결론

> **A라인과 B라인의 평균 토크에는 통계적으로 유의한 차이가 있습니다.**

### 핵심 결과

|항목|A라인|B라인|
|---|---|---|
|n|120|115|
|평균|35.21|35.74|
|차이||+0.53|
|검정||Welch t-test|
|p-value||0.0016|
|95% CI||0.20 ~ 0.86|

### 제조적 해석

> B라인의 토크가 평균적으로 약 0.53 높게 나타났습니다. 통계적으로 유의한 차이이지만 실제 제조 영향은 규격 및 공정 목표 대비 차이의 크기를 함께 판단해야 합니다.

### 주의사항

> 두 라인의 모델 구성 차이가 큰 경우 모델 효과가 라인 효과와 혼재될 수 있습니다.

### 추천 분석

> **동일 모델 조건에서 A/B라인을 다시 비교하는 것을 권장합니다.**

이것이 사용자가 실제 현장에서 가장 필요로 하는 형태입니다.

---

# 16. UC-03의 Benchmark Case 정의

향후 Agent 평가를 위해서는 단순 시나리오가 아니라 **Golden Case**로 만들어야 합니다.

예:

```
Case ID
= GC-UC03-001

Question
= "A라인과 B라인의 토크 차이가 있는지 확인해줘."

Expected Problem Model
= GROUP_COMPARISON

Response
= Torque

Factor
= Line

Groups
= A, B

Relationship
= Independent

Expected Method
= Welch t-test

Expected Outputs
= Mean
= Difference
= t
= df
= p
= CI
= Effect Size

Potential Confounders
= Model
= Shift
= Machine

Expected Finding
= Line difference observed

Evidence
= E2

Forbidden Conclusion
= "Line B is proven cause"

Recommended Next Analysis
= Model-controlled comparison
```

이렇게 해야 나중에 LLM 모델을 변경하거나 Prompt를 수정해도 **동일한 Benchmark로 Agent 성능을 회귀 테스트**할 수 있습니다.

---

# 17. UC-03에서 얻은 중요한 설계 원칙

이번 시나리오를 통해 한 가지 중요한 원칙이 추가됩니다.

> **통계 분석 방법의 선택은 질문의 문장만으로 결정하지 않고, 질문 + 데이터 구조 + 데이터 생성 과정 + 제조 맥락을 함께 고려한다.**

이를 Agent Architecture 관점에서 표현하면:

```
Natural Language
      +
Data Schema
      +
Data Generating Process
      +
Manufacturing Context
      ↓
Problem Model
      ↓
Analysis Plan
      ↓
Statistical Method
```

이 구조가 앞으로 모든 Use Case의 기본이 됩니다.

## 다음 단계: UC-05

다음은 **"설비별 CTQ 차이가 있는지 분석해줘."**입니다.

여기서는 2개 그룹을 넘어 **3개 이상의 그룹**을 다루게 됩니다.

따라서 Agent가 다음을 판단해야 합니다.

**3개 이상 그룹 → ANOVA/Welch ANOVA → 유의성 확인 → 어느 그룹이 다른가? → Post-hoc 선택 → Effect Size → 제조적 중요성 → 교란요인 → 추가 분석**

특히 **"ANOVA에서 유의하다"와 "어느 설비가 문제인가"는 서로 다른 질문**이라는 점을 Agent가 이해하도록 설계하는 것이 UC-05의 핵심이 됩니다.
