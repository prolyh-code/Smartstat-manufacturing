## 1. 이 프로젝트는 무엇인가

> **제조 현장의 질문을 통계적 판단으로 바꿔주는 사내 웹 애플리케이션.**
> 검증된 통계 엔진으로 독립 동작하며, 필요할 때 LLM Agent를 선택적으로 연결해
> 분석 방법 선택 · 다단계 분석 · 결과 해석 · 원인 탐색을 지원한다.

Minitab이나 JMP와 **통계 계산 능력으로 경쟁하지 않습니다.** 통계 비전문가인 제조 현장 실무자가 **적절한 분석을 고르고, 결과를 이해하고, 현장 판단을 내릴 수 있게** 하는 것이 제품의 존재 이유입니다.

**사용자에는 해외 생산 공장의 기술자가 포함됩니다.** 따라서 화면·툴팁·해석·보고서·오류 메시지 전부가 **한국어와 영어를 지원**해야 합니다(§8 및 `31-4`). 이는 부가 기능이 아니라 처음부터 구조에 반영해야 하는 요구입니다.

**이 앱은 PRISM 3단계 로드맵의 2단계입니다.** 1단계(문제 발견·공정 수준 평가)는 PRISM이 이미 운영 중이고, 2단계가 이 앱(원인 분석 → 대책 검증)이며, 3단계는 검증된 개선을 **지식화**하여 문제-원인-대책 순환을 고도화하는 것입니다. 2·3단계는 **순차 진행하되, 3단계에서 쓸 데이터가 2단계부터 쌓이도록 기록 계층을 2단계에 포함**합니다(Step 32·33). 3단계의 검색·추천은 구현하지 않습니다.

**현재 상태: 설계 완료(Step 1~33), 구현 착수 전.**

## 3. 절대 바꾸면 안 되는 것 — 제품 원칙 10개

**이 10개는 성능·편의를 이유로 완화할 수 없습니다.** 완화가 필요하다고 판단되면 구현을 멈추고 확인을 받으십시오. (출처: Step 31 DD-085)

| # | 원칙 | 구현 중 실제로 깨지기 쉬운 지점 |
|---|---|---|
| 1 | **LLM은 통계를 계산하지 않는다** | 해석 문장을 만들며 평균을 다시 계산하거나 반올림을 바꿈 |
| 2 | **Manual(AI OFF)은 LLM 없이 100% 동작한다** | 해석 생성이 LLM에 의존해 결과 화면이 비어 보임 |
| 3 | **Manual과 AI는 동일한 Statistical Engine을 쓴다** | AI 경로에 별도 간이 계산을 둠 |
| 4 | **모든 Tool 실행은 Rule Engine 검증을 거친다** | "이미 검증된 계획"이라며 우회 |
| 5 | **승인 범위를 벗어난 Tool 실행은 없다** | 편의상 계획 외 분석을 자동 추가 |
| 6 | **모든 LLM 호출은 AI Gateway를 통과한다** | 문장 하나 생성하려고 Provider 직접 호출 |
| 7 | **식별자 원문은 LLM에 전송되지 않는다** | 판단 품질을 위해 작업자 실명을 함께 보냄 |
| 8 | **관찰 데이터만으로 인과를 확정하지 않는다** | p값이 작다는 이유로 "원인이다"라고 서술 |
| 9 | **실행되지 않은 결과를 주장하지 않는다** | LLM이 수행하지 않은 분석 결과를 생성 |
| 10 | **화면의 모든 서술에 출처가 표기된다** | 통계 결과와 AI 해석이 한 문단에 섞임 |

## 4. 시스템 구조 한 장

```text
┌──────────── 사용자 개인 PC (브라우저) ─────────────┐
│  앱 화면 (서버 렌더링)      LLM Connector          │
│                            · 개인 계정 인증        │
│                            · 요청 패키지 전달만     │
└────────┬───────────────────────────┬──────────────┘
         │ HTTPS                     │ HTTPS
         ▼                           ▼
┌─────────────────────────┐      ┌──────────┐
│  회사 내 앱 서버          │      │   LLM    │
│                         │      │(개인계정) │
│  Orchestrator           │      └──────────┘
│  AI Gateway (인증 제외)   │  ① 여과된 요청 패키지 발급
│  Rule Engine            │  ② 브라우저가 LLM에 전달
│  Tool Registry          │  ③ 응답을 서버로 회송
│  Statistical Engine     │
│  Analysis State         │
│         │               │
│  Analysis Worker (N개)  │  ← 파싱·통계·보고서는 워커에서
└─────────┼───────────────┘
          ▼
  원본/중간포맷 스토리지 · 메타DB
```

**핵심 4가지**

1. **분석·통계·Rule·State·화면은 전부 서버.** 브라우저에 판단 로직은 없습니다.
2. **LLM 호출만 개인 PC에서.** 서버는 개인 LLM 자격증명을 **보관하지 않습니다**(DD-098).
3. **브라우저는 전달자이지 작성자가 아닙니다**(DD-099). 서버가 이미 여과를 끝낸 요청 패키지를 만들어 주고, 브라우저는 수정 없이 전송만 합니다. 가명화·식별자 제거·전송범위 판정은 원본에 접근 가능한 서버에서만 가능하기 때문입니다.
4. **분석 실행은 앱 서버가 아니라 워커에서**(DD-060). 100만 행 Excel 파싱이 웹 응답 스레드를 잡으면 다른 사용자 화면까지 느려집니다.

### 4-1. 4역할 분리 — 이 프로젝트의 근간

| 역할 | 담당 | 하지 않는 것 |
|---|---|---|
| **LLM** | 이해·계획·해석·가설·다음 분석 제안 | 계산, 결과 수정, 인과 확정 |
| **Statistical Engine** | 결정론적 계산 | 판단, 해석 |
| **Rule Engine** | 실행 가능 여부 통제 | 계산, 해석 |
| **Analysis State** | 분석 사실 보존 | 판단 |

| E-13 | 제조·기술 부서는 **PRISM에 대한 초기 거부감**이 있었고, 원인분석·대책수립까지 요구할 수 없는 상태였음. 따라서 기록 입력은 **강제할 수 없고**, 입력 부담을 LLM이 대신 지는 방식이어야 함(DD-124·DD-126) |
| E-14 | **설비 마스터(기종·제조사·도입연도)는 존재하지 않음.** 3단계에서 신설하며, 2단계는 설비 식별자를 **원본 표기 그대로 보존**하는 것으로 대비함(DD-134) |
| E-15 | **CTQ 표준화는 진행 중**이며 2단계 설계는 표준화를 전제로 함. PRISM이 CTQ 항목·데이터 품질을 점검·비교 기록하는 기능을 이미 보유 |

## 8. 구현 시 자주 틀리는 지점

경험상 이 항목들이 문서를 대충 읽으면 반드시 어긋납니다.

| 항목 | 올바른 구현 | 근거 |
|---|---|---|
| **세 가지 제외 필터** | 직렬화 제외 / LLM 전송 제외 / 로그 제외는 **서로 다른 3개 목록**입니다. 하나로 합치지 마십시오. 작업자 실명은 **저장은 하고**(화면 표시) 전송·로그는 금지입니다 | DD-079 |
| **두 가지 재시도** | Rule reject 후 **결정 재시도**(최대 2회)와 네트워크 실패 후 **전송 재시도**(최대 2회)는 별개 카운터입니다. 합치면 네트워크 오류가 "Agent 판단 실패"로 기록되어 평가가 왜곡됩니다 | DD-034 |
| **Agent 재개 지점** | 별도 체크포인트를 만들지 마십시오. 완료된 단계는 이미 Analysis State에 있으므로 **State가 곧 재개 지점**입니다 | DD-070 |
| **가명 매핑** | 세션 파일·DB·로그 어디에도 저장하지 마십시오. 원본에서 **재생성**합니다 | DD-083 |
| **대용량 Excel** | 분석할 때마다 재파싱하지 마십시오. 업로드 시 1회 파싱 → 열지향 중간 포맷 → 이후엔 필요한 열만 로드 | DD-064 |
| **보고서 생성** | 자동 생성하지 마십시오. 사용자가 버튼을 눌렀을 때만 Job으로 생성합니다 | DD-096 |
| **그래프** | 모든 분석 Tool에 **필수 그래프가 지정**되어 있습니다(31-1 §3). 그래프 없는 분석 결과 화면은 없습니다 | DD-092 |
| **표본이 적을 때** | n<5면 상자그림을 그리지 마십시오. 개별 점만 표시하고 경고합니다 | DD-095 |
| **로그아웃 순서** | LLM 연결 해제 → 작업 정리 → 앱 세션 무효화 순서입니다. 앱 세션을 먼저 끊으면 LLM 해제를 지시할 경로가 사라집니다 | DD-106 |
| **불변식** | 스키마 필드만 구현하고 끝내지 마십시오. 불변식 17개가 계약의 일부이며 각각 검증 지점이 지정되어 있습니다 | DD-082 |
| **다국어 — 문자열 하드코딩** | 화면에 나가는 문자열을 코드에 직접 쓰지 마십시오. 전부 언어 사전 키로 참조하며, 키가 없으면 **빌드가 실패**해야 합니다. 나중에 얹으면 하드코딩을 전부 찾아내야 합니다 | DD-114 |
| **다국어 — 데이터는 번역 금지** | `3호기`를 `Machine 3`으로 바꾸면 원본 Excel과 대조할 수 없습니다. 변수명·그룹 수준값은 **영어 화면에서도 원문 그대로**입니다. LLM 프롬프트에도 번역 금지를 명시합니다 | DD-113·117 |
| **다국어 — 오류 메시지** | 오류만은 언어 설정과 무관하게 **`[코드] + 한국어 + 영어`를 함께** 출력합니다. 해외 공장이 화면을 캡처해 본사와 소통하기 때문입니다 | DD-115 |
| **다국어 — 숫자 표기** | 로케일별 숫자 형식을 쓰지 마십시오. 소수점 `.`, 천단위 `,`, 날짜 ISO 8601 **고정**입니다. `3.14`와 `3,14` 혼동은 규격 판정을 뒤집습니다 | DD-119 |
| **다국어 — 해석 템플릿** | 문장 조각을 이어 붙이지 마십시오("평균이"+"낮"+"습니다"). 한국어 조사·어미와 영어 관사·복수가 반드시 깨집니다. **문장 단위 템플릿**을 언어별로 작성합니다 | DD-116 |
| **기록 — 입력을 강제하지 말 것** | 대책·검증 입력을 필수 항목으로 막아 세우지 마십시오. 제조·기술 부서의 협조를 아직 못 얻은 상태입니다(E-13). 빈 폼을 채우게 하는 대신 **사용자가 한 문장을 쓰면 LLM이 구조화하고 사용자는 확인만** 합니다 | DD-124 |
| **기록 — 원문을 반드시 남길 것** | LLM이 구조화한 필드만 저장하고 원문을 버리지 마십시오. `description_raw`에 **사용자가 실제로 쓴 문장을 그대로** 보존합니다. 3단계에서 구조화 스키마가 바뀌면 원문에서 다시 뽑아야 합니다 | DD-125 |
| **기록 — 설비 식별자 정규화 금지** | `3호기`를 `M3`으로 바꾸거나 공백·표기를 임의 정리하지 마십시오. 설비 마스터는 3단계에 생기며, 그때 **조인으로 소급 보완**하려면 원본 표기가 남아 있어야 합니다. DD-113과 같은 원칙입니다 | DD-134 |
| **기록 — 검증 완료 시 자동 Hold** | 보유기간 만료로 지우면 안 됩니다. `verdict` 확정 시 `retention_hold=true`가 **자동** 설정되며, 삭제 대상 선정 쿼리에서 **먼저 배제**합니다(삭제 후 필터링 아님) | DD-127 |
| **기록 — 3단계 기능은 만들지 말 것** | 유사 케이스 검색·대책 추천·지식 그래프는 **2단계 범위 밖**입니다. 2단계가 하는 일은 "나중에 그것을 만들 수 있는 데이터를 남기는 것"뿐입니다 | Step 32 |
| **기록 — 검증은 인과 확정이 아님** | `verdict=EFFECTIVE`를 "원인이 규명됨"으로 기록하지 마십시오. 측정 시스템 동일 여부·교란요인·부작용을 함께 남기고 **Evidence Level로 표기**합니다 | DD-128 |

## 10. 이 프로젝트를 한 문장으로

> **LLM은 판단을 돕되 계산하지 않고, 통계는 계산하되 판단하지 않으며, 그 사이를 규칙과 상태가 연결한다.**

이 구조 덕분에 인증 모델이 세 번 바뀌고 제품 형태가 데스크톱에서 웹앱으로 바뀌는 동안에도 핵심 설계는 무너지지 않았습니다. **구현에서도 이 경계를 지키는 것이 가장 중요합니다.**
