# 24-17. PASS/FAIL 로직

여기서는 단순 총점 방식보다 **Gate + Score** 구조를 권장합니다.

```

               /         \
             YES           NO
              │             │
```

# 24-19. Semantic Evaluation

LLM Agent 평가에서 특히 중요한 부분입니다.

최종 답변의 문장이 정확히 Golden Answer와 같을 필요는 없습니다.

예를 들어 다음 세 문장은 모두 허용해야 합니다.

> A라인의 평균 토크가 B라인보다 낮습니다.

> B라인의 평균 Torque가 A라인보다 높게 나타났습니다.

> 평균 기준으로 A Line < B Line입니다.

모두 동일한 의미입니다.

따라서 Evaluator는:

```
문장 일치
```

가 아니라:

```
Semantic Meaning
```

을 평가해야 합니다.

---

# 24-20. 그러나 숫자는 엄격하게

반대로 숫자는 semantic evaluation에 맡기면 안 됩니다.

예를 들어:

> 차이가 약 3 N·m입니다.

는 설명으로는 괜찮을 수 있지만, Golden Case의 정확성 평가에서는:

```
-2.628 N·m
```

를 기준으로 해야 합니다.

따라서:

```
숫자
→ Deterministic Evaluator

문장 의미
→ Semantic Evaluator
```

로 분리합니다.

이것이 매우 중요한 설계입니다.

# 24-24. Step 24에서 확정된 핵심 원칙

이번 단계에서 중요한 설계 원칙을 정리하면 다음과 같습니다.

### 원칙 1

**Golden Case는 단순 예상 답변이 아니다.**

### 원칙 2

**Golden Dataset과 Golden Case를 분리한다.**

### 원칙 3

**숫자는 Deterministic Evaluation을 사용한다.**

### 원칙 4

**자연어는 Semantic Evaluation을 사용한다.**

### 원칙 5

**Critical Error는 총점과 무관하게 FAIL이다.**

### 원칙 6

**Tool 선택과 Tool parameter를 모두 평가한다.**

### 원칙 7

**Finding, Evidence, Hypothesis, Causal Judgment를 서로 다른 객체로 평가한다.**

### 원칙 8

**Golden Case의 정답은 하나의 문장이 아니라 하나의 판단 구조다.**
