# Step 23. GC-UC03-001 Synthetic Dataset 설계

## 23-1. Dataset 설계 목표

이번 데이터셋은 다음 5가지를 동시에 검증하도록 설계합니다.

|검증 목적|데이터 설계|
|---|---|
|두 Line의 평균 차이|A/B에 실제 평균 차이 존재|

따라서 이 데이터셋은 단순한 t-test용 데이터가 아니라 **Agent Reasoning Test Dataset**입니다.

# 23-3. 가장 중요한 데이터 생성 구조

이번 Dataset의 핵심은 다음과 같습니다.

```
                    Model
                  /       \
                 /         \
              Line        Torque
                \           /
                 \         /
                  관찰된 차이
```

즉 `Model`이 Line별로 균등하게 분포하지 않습니다.

예를 들어:

```
Model A
   A Line 비중 ↑

Model B
   비교적 균등

Model C
   B Line 비중 ↑
```

그리고 Model 자체가 Torque에 영향을 줍니다.

따라서:

```
Line → Torque
```

라는 단순 관계를 관찰하더라도 실제로는

```
Line
 ↓
Model 구성 차이
 ↓
Torque
```

일 가능성이 있습니다.

이것이 **Confounding Test**입니다.

# 23-4. 생성된 Dataset의 실제 구조

재현 가능한 난수 seed를 사용해 1,840건을 생성하는 구조로 잡았습니다.

최종 생성 데이터에서 확인되는 Line별 표본 수는:

|Line|n|
|---|---|
|A|815|
|B|1,025|
|**합계**|**1,840**|

따라서 기존 Golden Case의 예시였던 `920 / 920`은 이제 **실제 Dataset의 기대값으로 사용하지 않는 것**이 맞습니다.

앞으로는 실제 생성 데이터에서 나온 값을 Golden Case의 기준값으로 확정해야 합니다.

---

# 23-5. Model × Line 구성

실제 생성 결과는 다음과 같습니다.

|Model|A Line|B Line|합계|
|---|---|---|---|
|A|419|237|656|
|B|211|249|460|
|C|185|539|724|
|**합계**|**815**|**1,025**|**1,840**|

이 구조가 상당히 좋습니다.

특히:

> **Model C가 B Line에 집중되어 있습니다.**

따라서 Agent가 단순히

> “B Line의 Torque가 높으므로 B Line의 공정이 원인이다.”

라고 판단하면 안 됩니다.

---

# 23-6. Torque 생성 논리

Torque는 다음과 같은 구조로 생성했습니다.

```
Torque
=
기본 수준
+
Model 효과
+
Line 효과
+
Random variation
```

개념적으로:

```
Torque = 165 + Model Effect + Line Effect + Error
```

Model 효과는:

```
Model A = 0
Model B = +2
Model C = +4
```

Line 효과는:

```
A Line = 0
B Line = +1.2
```

로 설정했습니다.

그리고 Line별 오차의 표준편차를:

```
A Line ≈ 5
B Line ≈ 7
```

로 설정하여 **명확한 unequal variance**가 발생하도록 했습니다.

---

# 23-7. 실제 생성 결과

실제 데이터의 핵심 통계량은 다음과 같습니다.

|통계량|A Line|B Line|
|---|---|---|
|n|815|1,025|
|Mean Torque|**166.252**|**168.881**|
|SD|**5.233**|**7.119**|
|Variance|약 27.39|약 50.68|

여기서 Agent가 발견해야 하는 중요한 사실은:

> **B Line의 평균이 높을 뿐 아니라 분산도 상당히 큽니다.**

따라서 단순 Student t-test보다 **Welch t-test를 우선 검토해야 합니다.**

---

# 23-8. 실제 Welch t-test 결과

실제 생성 데이터에 Welch t-test를 적용하면:

```
Mean A = 166.252
Mean B = 168.881

Difference = -2.628

t = -9.121

df = 1827.166

p < 0.0000000000000000001
```

95% Confidence Interval:

```
[-3.194, -2.063] N·m
```

Cohen's d:

```
d = -0.414
```

따라서 통계적으로는 매우 명확한 차이가 있습니다.

---

# 23-9. 그런데 여기서 Agent가 멈추면 안 됩니다

Agent가 다음처럼 답한다면 **불완전한 정답**입니다.

> A라인과 B라인의 평균 Torque에는 통계적으로 유의한 차이가 있습니다. B라인이 A라인보다 약 2.63 N·m 높습니다.

통계적으로는 맞습니다.

그러나 우리가 이 Golden Case에서 요구하는 Agent는 여기서 한 단계 더 나아가야 합니다.

왜냐하면:

```
Model 구성
        ↓
Line별로 크게 다름
        ↓
Model별 Torque 수준도 다름
```

이기 때문입니다.

---

# 23-10. Confounding이 실제로 존재하는지 확인

Model별 평균을 확인하면:

|Model|A/B 구성|Torque 수준|
|---|---|---|
|A|A Line 비중 높음|상대적으로 낮음|
|B|비교적 균등|중간|
|C|B Line 비중 높음|상대적으로 높음|

따라서 전체 데이터를 합쳐 보면:

```
B Line
  ↓
Model C 비중 높음
  ↓
Model C Torque 자체가 높음
  ↓
B Line 평균 Torque 상승
```

이라는 경로가 가능합니다.

즉 전체 Line 비교에서 관찰된 `-2.63 N·m`의 차이에는 **실제 Line 효과 + Model 구성 효과**가 섞여 있을 수 있습니다.

---

# 23-11. 동일 Model 기준으로 다시 비교

이제 Agent가 해야 할 다음 분석입니다.

> **Model별로 A/B Line을 다시 비교한다.**

실제 데이터에서:

### Model A

```
A: n=419
B: n=237

A mean = 165.077
B mean = 166.223

Difference = -1.146
p = 0.0326
```

### Model B

```
A: n=211
B: n=249

A mean = 166.374
B mean = 168.744

Difference = -2.370
p = 0.0000214
```

### Model C

```
A: n=185
B: n=539

A mean = 168.774
B mean = 170.112

Difference = -1.338
p = 0.00541
```

흥미로운 결과입니다.

**Model을 동일하게 놓고 비교해도 B Line이 높게 나타납니다.**

따라서 이 Dataset은 단순한 “가짜 Confounding”만을 넣은 것이 아닙니다.

오히려 Agent가 다음과 같이 추론해야 하는 더 현실적인 상황을 만들어 줍니다.

```
전체 비교
   ↓
Line 차이 매우 명확
   ↓
Model confounding 발견
   ↓
동일 Model 비교
   ↓
Line 차이가 여전히 존재
   ↓
Line effect 가설 강화
```

즉:

> Confounding이 발견되었다고 해서 원래 가설을 무조건 폐기하는 것이 아니라, **교란을 통제한 후 가설의 강도가 어떻게 변화하는지를 평가**해야 합니다.

이것이 우리가 만들려는 Agent의 중요한 지능입니다.

# 23-14. Defect_Flag의 역할

이번 Case에서 `Defect_Flag`는 핵심 분석 변수가 아닙니다.

하지만 향후 Agent가:

> “Torque 차이가 실제 불량과 연결되는가?”

라는 질문으로 확장할 수 있도록 포함시킵니다.

현재는 Target 대비 과도한 편차를 가진 값을 품질 이벤트로 정의하는 방식으로 구성할 수 있습니다.

예를 들어:

```
|Torque - Target| > 15
→ Defect_Flag = 1
```

실제 생성 데이터에서는:

|Line|Defect Rate|
|---|---|
|A|약 1.60%|
|B|약 3.12%|

정도로 나타났습니다.

하지만 Line과 Defect_Flag의 Chi-square 검정은:

```
p ≈ 0.0507
```

이므로 **5% 기준에서는 통계적으로 명확한 차이라고 단정하기 어렵습니다.**

이것도 좋은 테스트입니다.

즉 Agent가:

> “B Line의 Torque가 높으므로 B Line의 불량률도 유의하게 높다.”

라고 연결한다면 잘못된 추론입니다.

# 23-19. 이번 Step에서 아주 중요한 설계상의 발견

이번 Synthetic Dataset을 설계하면서 한 가지 중요한 방향이 명확해졌습니다.

**Golden Dataset은 단순히 통계 계산을 테스트하는 데이터가 되어서는 안 됩니다.**

앞으로 Golden Dataset을 세 종류로 나누는 것이 좋겠습니다.

### Type A — Statistical Golden Dataset

통계 계산 자체를 검증합니다.

```
정답 = 숫자
```

### Type B — Reasoning Golden Dataset

분석 방법과 분석 순서를 검증합니다.

```
정답 = 분석 경로
```

### Type C — Manufacturing Golden Dataset

Confounding, 실무적 의미, 인과성, Next Best Analysis까지 검증합니다.

```
정답 = 판단 구조
```

이번 **GC-UC03-001은 Type C에 해당하는 첫 번째 대표 Golden Case**로 볼 수 있습니다.

이 방향이 앞으로 상당히 중요합니다.
