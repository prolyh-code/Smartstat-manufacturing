# 0. 배경 — 지적된 공백

Ian의 확인 요청 중 두 가지가 실제 공백이었다.

> "분석에 사용되는 통계 분석 도구별로 어떤 그래프가 제공되는지 명문화 되어 있나요? 기본적인 그래프 도구는 이미 정의되어 있는 상태이나 그 외 분석 도구에는 정의되지 않은 것 같습니다."

**정확한 지적이다.** 현재 상태를 점검한 결과는 다음과 같다.

| 항목 | 현재 상태 |
|---|---|
| 그래프 종류 목록 | **있음** — Baseline §26에 11종 나열 |
| 시각화 Tool 등록 | **있음** — Step 31 §3-2 Visualization 카테고리 5종 |
| **분석 Tool ↔ 그래프 매핑** | **없음** ← 이 문서가 채운다 |
| **그래프별 필수 구성요소** | **없음** ← 이 문서가 채운다 |
| SVG 출력 원칙 | 있음(Baseline §26) — 다만 Step 31에서 PDF 병기 |

매핑이 없으면 구현 단계에서 개발자가 임의로 정하게 되고, **"t-test를 했는데 그래프가 없다"거나 "ANOVA에 히스토그램만 나온다" 같은 결과**가 나온다. 원 기획서의 핵심 원칙 중 하나가 *"P-value보다 그래프를 먼저 보여준다"*였으므로 이는 제품 가치에 직결된다.

# 1. 출력 형식 확정

**DD-090 · 앱이 생성하는 모든 그래프는 SVG로 출력한다. 래스터 이미지(PNG 등)는 사용자가 명시적으로 내보내기를 요청할 때만 생성한다.**

| 근거 | 내용 |
|---|---|
| 확대해도 깨지지 않음 | 규격선 근처의 미세한 차이를 확대해 확인하는 것이 제조 현장의 실제 사용 방식 |
| 텍스트가 텍스트로 남음 | 보고서에서 검색·복사 가능. 스크린리더 접근성 |
| HTML 보고서에 인라인 삽입 가능 | 별도 이미지 파일 없이 **단일 HTML 파일로 완결**(§7) |
| 서버 렌더링에 적합 | 이미지 래스터화 엔진(headless browser 등) 불필요 → 워커 부담 감소 |
| 용량 | 통계 그래프는 요소 수가 적어 SVG가 PNG보다 대체로 작음 |

**Status:** 확정 제안

# 2. 시각화 Tool 목록 확장

**DD-091 · 시각화 Tool을 5종에서 10종으로 확장한다.**

Step 31 §3-2의 5종(`histogram`, `box_plot`, `scatter_plot`, `comparison_plot`, `trend_chart`)으로는 §4의 매핑을 충족할 수 없다. 특히 **대응표본 비교, 사후검정 결과, 회귀 진단, 정규성 확인**에 쓸 그래프가 없다.

| # | Tool | 용도 | 비고 |
|---|---|---|---|
| 1 | `histogram` | 분포 확인 | 규격선·목표선 표시 지원 |
| 2 | `box_plot` | 그룹 간 분포 비교, 이상값 | 다중 그룹 지원 |
| 3 | `scatter_plot` | 두 변수 관계 | 회귀선·신뢰대 옵션 포함 |
| 4 | `bar_chart` | 범주 빈도·비율 | 그룹화·누적 옵션, 오차막대 옵션 |
| 5 | `line_chart` | 시계열 추이 | 기존 `trend_chart`를 개칭 |
| 6 | **`mean_ci_plot`** | 그룹별 평균 ± 신뢰구간 | 기존 `comparison_plot`을 구체화 |
| 7 | **`paired_plot`** | 대응표본 전후 연결선 | 대응 t-test 전용 |
| 8 | **`difference_ci_plot`** | 쌍별 차이와 신뢰구간 | 사후검정 결과 표시, 0선 기준 |
| 9 | **`residual_plot`** | 회귀 잔차 진단 | 잔차 vs 적합값 |
| 10 | **`normal_probability_plot`** | 정규성 시각 확인 | 정규확률도(Q-Q) |

기존 `comparison_plot`은 이름만으로 무엇을 그리는지 알 수 없어 `mean_ci_plot`으로 구체화한다. `trend_chart`는 `line_chart`로 개칭하여 "추세 분석"이라는 통계적 의미와 "선 그래프"라는 형태를 분리한다.

**Status:** 확정 제안

# 3. 분석 도구별 그래프 매핑

**DD-092 · 모든 통계 분석 Tool은 아래 표에 따라 기본 그래프(필수)와 보조 그래프(선택)를 함께 산출한다. 기본 그래프가 없는 분석 Tool은 존재하지 않는다.**

표기: **필수** = 결과 화면에 항상 표시 / 선택 = 사용자 요청 또는 조건 충족 시

## 3-1. Data / EDA

| 분석 Tool | 필수 그래프 | 선택 그래프 | 비고 |
|---|---|---|---|
| `profile_data` | `bar_chart` (변수별 결측률) | — | 데이터 구조 개요 |
| `check_data_quality` | `bar_chart` (문제 유형별 건수) | `box_plot` (이상값 후보) | — |
| `summarize_variables` | 수치형 → `histogram`<br>범주형 → `bar_chart` | `box_plot` | 변수 유형에 따라 분기 |
| `detect_missing` | `bar_chart` (변수별 결측률) | — | — |
| `detect_duplicates` | `bar_chart` (중복 건수) | — | 건수가 0이면 그래프 생략 |
| `detect_outliers` | `box_plot` (이상값 개별 표시) | `scatter_plot` (시간축) | — |
| `descriptive_statistics` | `histogram` + `box_plot` | `normal_probability_plot` | 2개 동시 표시 |
| `distribution_analysis` | `histogram` | `normal_probability_plot` | 규격선 필수 표시 |
| `trend_analysis` | `line_chart` | `bar_chart` (기간 집계) | 시간 변수 필요 |
| `outlier_analysis` | `box_plot` | `scatter_plot` (시간축) | — |

## 3-2. Comparison — 이 프로젝트의 중심

| 분석 Tool | 필수 그래프 | 선택 그래프 | 그래프가 보여줘야 하는 것 |
|---|---|---|---|
| `one_sample_t_test` | `histogram` (목표값 기준선 표시) + `mean_ci_plot` | — | 평균의 CI가 목표값을 포함하는가 |
| `two_sample_t_test` | `box_plot` (그룹별) + `mean_ci_plot` | `histogram` (그룹 중첩) | 두 그룹의 분포 차이와 평균 CI 중첩 여부 |
| **`welch_t_test`** | `box_plot` + `mean_ci_plot` | `histogram` (그룹 중첩) | 위와 동일. **분산 차이가 box 폭으로 보여야 함** |
| `paired_t_test` | **`paired_plot`** + `histogram` (차이값) | `box_plot` (차이값) | 개체별 변화 방향과 차이의 분포 |
| `anova` | `box_plot` (다중 그룹) + `mean_ci_plot` | `histogram` (그룹별) | 그룹 간 평균 차이와 그룹 내 산포 |
| `welch_anova` | `box_plot` + `mean_ci_plot` | — | 위와 동일 |
| `tukey_posthoc` | **`difference_ci_plot`** | `box_plot` | 어느 쌍이 유의한가 — **0선을 넘는 CI가 유의하지 않은 쌍** |
| `games_howell` | **`difference_ci_plot`** | `box_plot` | 위와 동일 |
| **`chi_square_test`** | `bar_chart` (그룹별 비율, 오차막대) | `bar_chart` (관측 vs 기대빈도) | 비율 차이의 크기와 불확실성 |
| **`proportion_test`** | `bar_chart` (비율 + CI) | — | 비율 CI의 중첩 여부 |

## 3-3. Relationship

| 분석 Tool | 필수 그래프 | 선택 그래프 | 비고 |
|---|---|---|---|
| `pearson_correlation` | `scatter_plot` (추세선 포함) | — | 상관계수만으로는 비선형·이상값을 놓친다 |
| `spearman_correlation` | `scatter_plot` | `scatter_plot` (순위 변환) | — |
| `simple_regression` | `scatter_plot` (회귀선 + 신뢰대) + **`residual_plot`** | `normal_probability_plot` (잔차) | **잔차 그래프 필수** — 회귀 가정 확인 |

**회귀에서 `residual_plot`을 필수로 둔 이유:** R²와 회귀계수만 보고 판단하면 비선형 관계나 이분산을 놓친다. 잔차 그래프는 회귀의 타당성을 시각적으로 확인하는 유일한 수단이며, 통계 비전문가에게도 "점들이 무늬 없이 흩어져 있으면 괜찮다"는 판단 기준을 줄 수 있다.

## 3-4. Manufacturing

| 분석 Tool | 필수 그래프 | 선택 그래프 | 비고 |
|---|---|---|---|
| `defect_rate` | `bar_chart` 또는 `line_chart` (기간별) | — | 시간 변수 유무로 분기 |
| `group_defect_rate` | `bar_chart` (그룹별 비율 + CI) | — | CI 표시가 중요 — 표본 수가 다르면 비율 차이의 의미가 달라짐 |

# 4. 그래프 필수 구성요소

**DD-094 · 모든 그래프는 아래 공통 요소를 포함하며, 제조 맥락 요소는 해당 데이터가 있을 때 항상 표시한다.**

## 4-1. 공통 필수 요소

| 요소 | 규칙 |
|---|---|
| 축 레이블 | 변수명 + **단위**(N·m, mm, % 등) |
| 표본 수 | 그룹별 n을 축 레이블 또는 범례에 표시 (예: `A라인 (n=815)`) |
| 제목 | 무엇을 무엇으로 비교/표시하는지 |
| 범례 | 계열이 2개 이상일 때 |
| 결측 처리 표기 | 제외된 건수가 있으면 각주 (예: `결측 7건 제외`) |

## 4-2. 제조 맥락 요소

| 요소 | 표시 조건 | 표현 |
|---|---|---|
| **규격 상·하한 (USL/LSL)** | 규격 변수가 지정된 경우 | 수평·수직 기준선 + 라벨 |
| **목표값 (Target)** | 목표 변수가 지정된 경우 | 별도 스타일의 기준선 |
| **규격 이탈 데이터** | 규격이 지정되고 이탈 값이 있는 경우 | 해당 점을 구분 표시 |

규격선 표시가 이 제품을 일반 통계 도구와 구분하는 지점이다. **"평균이 다르다"보다 "규격 안에 있는가"가 현장의 실제 질문**이기 때문이다.

단, §Step 28-1 DD-057에 따라 규격값은 C3(공정 기밀)이므로 **화면·보고서에는 실값을 표시하되 LLM 전송 여부는 별도 정책**을 따른다. 그래프 이미지 자체가 LLM에 전송되는 일은 없다(Step 27 — LLM은 ToolResult 수치만 받는다).

## 4-3. 표본 수에 따른 표현 규칙

**DD-095 · 그룹 표본 수가 임계값 미만이면 분포 요약 그래프 대신 개별 값을 표시한다.**

| 조건 | 표현 |
|---|---|
| n ≥ 20 | `box_plot` 정상 표시 |
| 5 ≤ n < 20 | `box_plot` + **개별 점 중첩 표시** |
| n < 5 | box를 그리지 않고 **개별 점만 표시** + 경고 |

**Reason:** 표본이 3개인데 사분위수 상자를 그리면 그림이 실제보다 훨씬 많은 정보를 가진 것처럼 보인다. 통계 비전문가일수록 그림을 그대로 신뢰하므로, **표본이 적다는 사실 자체가 그림에서 드러나야 한다.** 이 임계값은 Step 28 DD-044(재식별 경고 임계 5)와도 일치하므로 한 번의 검사로 두 경고를 함께 표시할 수 있다.
**Status:** 확정 제안

# 5. 보고서 사양

## 5-1. 선택적 생성

**DD-096 · 보고서는 자동 생성되지 않는다. 사용자가 [보고서 생성] 버튼을 누른 시점에만 생성한다.**

| 항목 | 규칙 |
|---|---|
| 생성 시점 | 사용자의 명시적 요청 시에만 |
| 버튼 위치 | S-06 분석 결과 화면 하단, S-07 AI 작업공간 하단, S-10 Finding/Evidence 보드 |
| 생성 방식 | Job(`job_type = REPORT`)으로 큐에 투입 — 동기 생성하지 않음(Step 29 DD-060) |
| 진행 표시 | 생성 중 진행 상태 표시, 완료 시 알림 |
| 범위 선택 | 생성 시 포함할 분석 범위를 사용자가 선택 (현재 분석만 / 세션 전체 / 선택한 항목) |

**Reason:** 자동 생성은 세 가지 비용을 만든다 — ① 워커 자원을 쓰고 ② 보유기간 관리 대상(A4 자산)을 불필요하게 늘리며 ③ 사용자가 원하지 않는 파일이 목록에 쌓인다. 분석은 여러 번 반복되지만 보고서가 필요한 시점은 그중 일부다.
**Status:** 확정 제안

## 5-2. HTML 단일 형식

**DD-097 · 보고서 형식은 HTML로 한다. MVP에서 PDF는 생성하지 않는다.**

Step 31 §3-5는 "PDF, HTML"로 병기했으나 **HTML 단일로 확정**한다.

| 근거 | 내용 |
|---|---|
| SVG 인라인 | 그래프가 SVG이므로 HTML에 그대로 삽입 가능 → **이미지 파일 없는 단일 파일** |
| 래스터화 불필요 | PDF 생성에는 headless browser 등 별도 렌더링 엔진이 필요하다. 워커 의존성과 장애 지점이 하나 줄어든다 |
| 확대·검색 | 현장에서 그래프를 확대해 보거나 값을 검색하는 사용이 가능 |
| 인쇄 | 브라우저 인쇄 기능으로 PDF 저장이 가능하므로 **PDF 요구는 대체된다** |
| 반출 통제 | 단일 HTML 파일이므로 다운로드 기간 관리(Step 29 DD-073)가 단순해진다 |

**PDF가 필요한 경우**(사외 제출, 전자결재 첨부 등)는 Phase 2에서 검토한다. 사용자는 브라우저 인쇄로 PDF를 만들 수 있다.
**Status:** 확정 제안

| # | 섹션 | AI OFF 시 |
