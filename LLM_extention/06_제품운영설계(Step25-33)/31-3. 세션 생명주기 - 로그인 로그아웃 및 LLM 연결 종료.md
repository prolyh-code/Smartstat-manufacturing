# 0. 문제 정의

Step 31-2에서 LLM 호출을 브라우저로 옮기면서 **이 앱에는 서로 다른 두 개의 세션이 존재**하게 되었다.

| 세션 | 주체 | 위치 | 인증 |
|---|---|---|---|
| **앱 세션** | 앱 서버 | 서버(세션 토큰) | 앱 ID/PW (DD-054) |
| **LLM 연결 세션** | 사용자 브라우저 | 개인 PC | 개인 LLM 계정 (DD-061·DD-098) |

**두 세션의 생명주기가 어긋나면 다음과 같은 상태가 발생한다.**

```text
① 앱에서 로그아웃했는데 브라우저에는 LLM 인증이 살아 있음
② 앱 세션이 타임아웃으로 끊겼는데 LLM 연결 표시는 여전히 "연결됨"
③ Agent 분석이 진행 중인 상태에서 로그아웃 → 작업이 어디서 멈췄는지 불명
④ 브라우저를 강제 종료 → 서버 세션이 계속 살아 있음
⑤ 다른 PC에서 같은 계정으로 로그인 → 두 세션이 같은 분석을 동시 수정
```

①②는 보안·비용 문제이고, ③④⑤는 데이터 정합성 문제다. 이 문서가 다섯 가지를 모두 처리한다.

# 1. 기본 원칙

**DD-104 · LLM 연결 세션은 앱 세션에 종속된다. 앱 세션이 종료되면 LLM 연결도 반드시 함께 종료된다. 그 역은 성립하지 않는다(LLM 연결만 해제해도 앱은 계속 사용 가능).**

```text
         앱 세션 (상위)
              │  종속
              ▼
        LLM 연결 세션 (하위)

  앱 세션 종료  ──► LLM 연결 반드시 종료
  LLM 연결 해제 ──► 앱 세션은 유지 (Manual 계속)
```

**Reason:** 앱 세션은 "이 사람이 이 앱을 쓸 자격이 있는가"를, LLM 연결은 "이 사람이 자기 계정으로 AI를 쓰겠다"를 뜻한다. 전자가 사라졌는데 후자가 남아 있을 이유가 없다. 반대로 LLM 연결만 끊는 것은 Baseline DD-004(LLM은 optional layer)의 정상 동작이다.
**Status:** 확정 제안

## 1-1. 상태 모델

```text
        ┌──────────────┐
        │  비로그인     │
        └──────┬───────┘
               │ 로그인 성공
               ▼
        ┌──────────────────────┐
        │  로그인 · LLM 미연결   │◄────┐
        │  (Level 0 Manual만)   │     │ [AI 연결 해제]
        └──────┬───────────────┘     │ 인증 실패
               │ [AI 연결] 성공        │ 한도 소진
               ▼                      │
        ┌──────────────────────┐     │
        │  로그인 · LLM 연결됨   │─────┘
        │  (Level 0~3 전체)     │
        └──────┬───────────────┘
               │ 로그아웃 / 세션 만료 / 강제 종료
               ▼
        ┌──────────────┐
        │  비로그인     │  ← LLM 연결도 반드시 해제된 상태
        └──────────────┘
```

**DD-105 · 로그인 직후의 LLM 연결 상태는 항상 "미연결"이다. 이전 세션의 LLM 연결을 자동으로 복원하지 않는다.**

**Reason:** 자동 복원은 두 가지 문제를 만든다. ① 사용자가 AI를 쓸 의사가 없는데도 연결 상태가 되어, 실수로 AI 기능을 눌렀을 때 본인 계정에 비용이 발생한다. ② "내 LLM 계정이 지금 연결되어 있는가"를 사용자가 의식하지 못하게 된다. 개인 비용 부담 구조(DD-061)에서는 **연결이 항상 명시적 행위여야 한다.**

단, 자격증명을 브라우저에 기억해 두는 것은 별개다 — 기억해 두었다면 [AI 연결] 클릭 한 번으로 연결되며, 재입력은 필요 없다. **기억은 편의이고 연결은 의사표시**다.
**Status:** 확정 제안

```text

         ▼
② 서버: 인증 → 권한 등급 조회 → 앱 세션 토큰 발급
         │       (GENERAL / ENGINEER / ADMIN)
         ▼
③ 서버: 기존 활성 세션 확인 → 있으면 §5 동시 로그인 정책 적용
         │
         ▼
④ 서버: 이 사용자의 미완료 세션(PAUSED) 조회
         │
         ▼
⑤ 브라우저: LLM 연결 상태 = 미연결 (DD-105)
         │       저장된 자격증명이 있으면 "연결 가능" 표시
         ▼
⑥ 홈(S-01) 진입
   · 이어서 분석할 세션이 있으면 목록 표시
   · 헤더에 [AI: 미연결] 표시
```

## 2-1. 로그인 직후 화면 표시

```text
┌──────────────────────────────────────────────────────────┐
│ SmartStat          홍길동 (품질보증2팀)   [AI: 미연결 ▾]  [로그아웃] │
├──────────────────────────────────────────────────────────┤
│  이어서 분석할 항목이 2건 있습니다                           │
│  ⏸ A라인/B라인 토크 차이 — AI 연결이 필요한 단계에서 대기 중   │
│  ● 3호기 불량률 증가 원인 — 분석 완료, 보고서 미생성          │

```

헤더의 AI 연결 상태 표시는 **항상 보이는 위치에** 둔다. 사용자가 "지금 내 계정이 연결되어 있는지"를 언제든 확인할 수 있어야 한다.

# 3. 로그아웃 시퀀스 — 순서가 중요하다

**DD-106 · 로그아웃은 LLM 연결 해제 → 진행 중 작업 정리 → 앱 세션 무효화 순서로 수행한다. 앱 세션을 먼저 끊으면 LLM 해제를 지시할 경로가 사라진다.**

```text
사용자가 [로그아웃] 클릭
         │
         ▼
① 진행 중 작업 확인
   · Agent 분석 진행 중?  · 보고서 생성 중?  · 업로드 파싱 중?
         │
         ├─ 있으면 → 확인 다이얼로그 (§3-1)
         │
         ▼
② LLM 연결 해제  ★ 가장 먼저
   · 브라우저 메모리의 인증 토큰 폐기
   · 공급자 세션 종료 호출 (지원되는 경우)
   · "기억하지 않음" 설정이면 저장된 자격증명도 삭제
   · 진행 중이던 LLM 요청이 있으면 취소
         │
         ▼
③ 진행 중 작업 정리
   · LLM 필요 단계 → 세션 PAUSED로 전환 후 저장 (Step 31-2 DD-102)
   · LLM 불필요 작업(파싱·통계·보고서) → 서버에서 계속 진행
   · Analysis State 저장 (Step 29 DD-052)
         │
         ▼
④ 앱 세션 무효화
   · 서버: 세션 토큰 폐기, 이후 요청 거부
   · 진행 중 Job의 소유자 세션 참조 해제
         │
         ▼
⑤ 브라우저 정리
   · 세션 스토리지 비우기
   · 화면의 분석 데이터·결과 제거
         │
         ▼
⑥ 로그인 화면으로 이동 + 완료 표시
```

## 3-1. 진행 중 작업이 있을 때의 확인

```text
┌────────────────────────────────────────────────────┐
│ 로그아웃                                             │
├────────────────────────────────────────────────────┤
│ 진행 중인 작업이 있습니다.                             │
│                                                    │
│  ● AI 원인 분석 — 5단계 중 3단계 진행 중              │
│    로그아웃하면 여기서 멈추고 저장됩니다.               │
│    다시 로그인해 이어서 진행할 수 있습니다.             │
│                                                    │
│  ● 보고서 생성 — 진행 중                              │
│    로그아웃해도 서버에서 계속 생성됩니다.               │
│                                                    │
│ AI 연결도 함께 해제됩니다.                             │
│                                                    │
│              [ 로그아웃 ]        [ 취소 ]            │
└────────────────────────────────────────────────────┘
```

**어떤 작업이 멈추고 어떤 작업이 계속되는지를 구분해서 알린다.** 이것이 Step 31-2 DD-102(LLM 필요 단계만 PAUSED)의 사용자 경험상 표현이다.

## 3-2. LLM 연결만 해제

로그아웃과 별개로 **AI 연결만 끊는 동작**을 제공한다.

```text
[AI: 연결됨 ▾]
   ├─ 사용량 보기
   ├─ 연결 설정
   └─ AI 연결 해제      ← 앱은 계속 사용
```

해제 시: 인증 토큰 폐기 → Level 0으로 하향 → **Analysis State 전량 보존**(Step 26 DD-014) → Manual 분석 계속.

# 4. 비정상 종료 처리

정상 로그아웃만 처리하면 실제 운영에서 대부분의 종료를 놓친다. 사용자는 보통 로그아웃 버튼을 누르지 않고 **탭을 닫거나 브라우저를 끈다.**

**DD-107 · 브라우저 측 정리는 최선 노력(best-effort)으로만 취급하고, 세션 종료의 실질적 보장은 서버 측 만료로 확보한다.**

| 상황 | 브라우저 동작 | 서버 동작 |
|---|---|---|
| 탭 닫기 / 새로고침 | `beforeunload`에서 LLM 토큰 폐기 시도 | 하트비트 중단 감지 → 유휴 타임아웃 시작 |
| 브라우저 강제 종료 | 정리 불가 | 동일 (타임아웃) |
| PC 종료·절전 | 정리 불가 | 동일 |
| 네트워크 단절 | 재연결 시도 | 타임아웃 전까지 세션 유지 |
| 앱 세션 만료 | 만료 통지 수신 시 LLM 즉시 해제 | 세션 무효화 |

## 4-1. 서버 측 최종 안전장치

**DD-108 · 앱 세션이 무효화되면 서버는 LLM 요청 패키지 발급을 거부한다. 브라우저에 LLM 인증이 남아 있어도 앱을 통한 LLM 사용은 불가능하다.**

이것이 이 설계의 **핵심 안전장치**다. Step 31-2 DD-099에 따라 **브라우저는 스스로 프롬프트를 만들 수 없고 서버가 발급한 요청 패키지만 전달**할 수 있으므로, 서버가 발급을 중단하면 그것으로 끝난다.

```text
브라우저에 LLM 토큰이 남아 있음
        │
        ▼
서버에 요청 패키지 발급 요청
        │
        ▼
서버: 앱 세션 무효 → 거부 (401)
        │
        ▼
브라우저: 전달할 것이 없음 → LLM 호출 불가
        └─► 화면에 "세션이 만료되었습니다. 다시 로그인해 주세요"
```

브라우저 측 정리가 실패해도 **앱을 통한 LLM 사용과 비용 발생은 서버에서 차단**된다. (사용자가 앱과 무관하게 자기 브라우저에서 LLM 서비스를 직접 쓰는 것은 이 앱의 통제 범위가 아니며, 통제해서도 안 된다.)
**Status:** 확정 제안

## 4-2. 재접속 시 정리

다음 로그인 시 서버가 이전 세션의 잔여물을 정리한다.

- 소유자 세션이 만료된 채 `RUNNING`으로 남은 Job → heartbeat 규칙에 따라 처리(Step 29 DD-071)
- `WAITING_APPROVAL` 상태로 방치된 세션 → `PAUSED`로 전환(Step 29 §5-8)
- LLM 대기 상태(`WAITING_CLIENT_LLM`)로 방치된 Job → 타임아웃 후 재시도 또는 PAUSED

# 5. 세션 타임아웃

**DD-109 · 유휴 타임아웃과 절대 타임아웃을 함께 적용하되, 서버에서 작업이 진행 중인 동안은 유휴로 판정하지 않는다.**

| 항목 | 기본값(제안) | 비고 |
|---|---|---|
| 유휴 타임아웃 | **60분** | 제조 현장은 자리 비움이 잦음. 30분은 짧다 [추론] |
| 절대 타임아웃 | **12시간** | 교대 근무 1회분을 넘지 않도록 |
| 만료 예고 | 만료 5분 전 경고 + [연장] | — |
| 진행 중 작업 | **유휴로 계산하지 않음** | 분석이 10분 걸리는 동안 세션이 끊기면 안 됨 |

관리자 콘솔에서 조정 가능하게 한다(Step 29 §7-1 사용자·권한 영역).

## 5-1. 만료 시 동작

```text
만료 5분 전
┌────────────────────────────────────────────┐
│ 5분 후 자동 로그아웃됩니다.                   │
│ 진행 중인 분석은 저장됩니다.                  │
│                   [ 계속 사용 ]  [ 로그아웃 ] │
└────────────────────────────────────────────┘

만료 시 → §3의 로그아웃 시퀀스를 자동 실행 (②부터)
```

# 6. 동시 로그인

**DD-110 · 같은 계정의 동시 활성 세션은 1개로 제한한다. 새 로그인이 발생하면 기존 세션을 종료한다.**

```text
PC-A 로그인 사용 중
         │
PC-B 에서 같은 계정 로그인
         │
         ▼
PC-B: "이 계정이 다른 곳에서 사용 중입니다.
       계속하면 기존 접속이 종료되고 진행 중인 분석은 저장됩니다.
                              [ 계속 ]  [ 취소 ]"
         │ 계속
         ▼
PC-A: 즉시 종료 통지 → LLM 연결 해제 → 세션 저장 → 로그인 화면
PC-B: 로그인 완료 (PAUSED 세션 목록에서 이어하기 가능)
```

**Reason:** 세 가지가 겹친다. ① **개인 PC 전제**(E-1)에서 동시 접속은 정상 사용 패턴이 아니다. ② 개인 계정 LLM 비용이 두 곳에서 동시에 발생하면 사용자가 추적하기 어렵다. ③ Step 29 DD-067(낙관적 잠금)은 같은 세션의 동시 수정을 *감지*하지만, 애초에 동시 접속을 막으면 그 충돌 자체가 줄어든다.

단일 세션 강제가 불편을 만드는 경우(공정 사무실과 현장 단말을 오가며 사용 등)는 운영 후 재검토한다.
**Status:** 확정 제안

# 7. 상태 표시 규약

**DD-111 · 앱 세션과 LLM 연결 상태를 헤더에 항상 표시하고, 두 상태를 구분해서 보여준다.**

| 표시 | 의미 |
|---|---|
| `홍길동 (품질보증2팀)` | 앱 세션 — 누구로 로그인했는가 |
| `[AI: 미연결]` | LLM 미연결. 클릭 시 연결 설정 |
