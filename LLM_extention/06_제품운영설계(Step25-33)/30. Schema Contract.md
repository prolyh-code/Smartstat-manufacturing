Baseline DD-012는 *"Product UX와 LLM operating architecture를 schema 확정보다 먼저 설계한다"*를 CONFIRMED로 두었다. 그 순서를 지킨 결과, 지금 계약에 들어가야 할 필드가 **화면과 운영 요구에서 역산되어 도출된 상태**다.

# 6. 세 가지 제외 필터 — 서로 다른 집합이다

**DD-079 · 직렬화 제외 / LLM 전송 제외 / 로그 기록 제외는 서로 다른 세 개의 필터로 정의하며, 하나로 합치지 않는다.**

| `reproducibility.group_summary` | ○ | ○ | ○ |
| 프롬프트 전문 | ✕ | — | △ 관리자 설정(90일) |

# 8. 스키마 버전과 호환성

Step 29에서 세션(A3)의 보유기간을 2년으로 정했다. **2년 동안 스키마는 반드시 바뀐다.** 2년 전 세션을 오늘 코드로 열 수 있어야 한다.

**DD-081 · 모든 영속 객체는 `schema_version`을 갖는다. 스키마 변경은 아래 규칙을 따른다.**

| 변경 유형 | 허용 | 처리 |
|---|---|---|
| 선택 필드 추가 | ○ | minor 증가. 구버전 문서는 기본값으로 읽음 |
| 열거형 값 추가 | ○ | minor 증가. 알 수 없는 값은 `UNKNOWN`으로 읽고 경고 |
| 필드 의미 변경 | **✕** | 새 필드를 추가하고 기존 필드는 폐기 표시 |
| 필드 삭제 | **✕** | 폐기 표시만. 실제 제거는 보유기간 경과 후 |
| 필수 필드 추가 | 조건부 | major 증가 + 마이그레이션 스크립트 필수 |

**읽기는 구버전 호환(backward compatible)을 보장하고, 쓰기는 항상 현재 버전으로 한다.** 구버전 세션을 연 뒤 새 분석을 추가하면 그 세션은 현재 버전으로 승격된다.
