## 2. 개발 배경

제조 현장에서는 생산·품질·설비·공정 데이터를 지속적으로 수집하고 있지만, 실제 데이터를 통계적으로 분석하여 의사결정에 활용하는 수준에는 상당한 차이가 존재한다.

현재 활용 가능한 통계 도구는 매우 다양하다.

- Microsoft Excel
    
- Minitab
    
- JMP
    
- Python / R
    
- BI Dashboard
    
- LLM 기반 통계 분석
    

그러나 이러한 도구들은 통계 전문가에게는 강력하지만 일반적인 제조 현장 사용자에게는 다음과 같은 접근성 문제가 있다.

### 주요 문제

1. **어떤 통계 분석을 사용해야 하는지 모른다.**
    
2. 통계 용어가 어렵다.
    
3. P-value, Confidence Interval, F-value 등의 의미를 직관적으로 이해하기 어렵다.
    
4. 분석 결과는 나오지만 **“그래서 공정에 문제가 있는가?”**를 판단하기 어렵다.
    
5. 분석 결과를 그래프로 표현하고 보고서로 만드는 데 추가 작업이 필요하다.
    
6. 제조 현장의 실제 문제와 통계 분석 메뉴가 직접 연결되어 있지 않다.
    

따라서 본 프로젝트는 기존 통계 프로그램의 기능을 단순히 축소하여 만드는 것이 아니라,

> **“제조 현장의 질문 → 적절한 통계 방법 선택 → 분석 → 시각화 → 쉬운 해석 → 현장 판단”**

을 하나의 흐름으로 제공하는 것을 목표로 한다.

# 5. 사용자의 핵심 문제 정의

사용자는 일반적으로 다음과 같은 질문을 한다.

### 문제 1

> “A 공정과 B 공정의 측정값이 다른가?”

→ 2-Sample t-test

### 문제 2

> “변경 전과 변경 후의 품질 수준이 달라졌는가?”

→ Paired t-test

### 문제 3

> “세 개 이상의 조건에서 평균 차이가 있는가?”

→ ANOVA

### 문제 4

> “어느 조건에서 차이가 발생했는가?”

→ Post-hoc Test

### 문제 5

> “온도가 올라가면 불량률 또는 치수가 변하는가?”

→ Correlation / Regression

### 문제 6

> “현재 공정 데이터가 어떤 분포를 가지고 있는가?”

→ Histogram / Box Plot

### 문제 7

> “목표값과 실제 평균이 다른가?”

→ 1-Sample t-test

따라서 앱의 첫 화면부터 통계학 용어를 나열하는 방식보다 **현장 질문 중심의 접근**을 제공한다.

# 12. 1-Sample t-test

> “현재 공정 평균이 목표값과 다른가?”

예:

Target = 35 mm

Sample Mean = 35.8 mm

앱은 다음과 같이 설명한다.

> 기준값 35 mm와 비교했을 때 현재 데이터의 평균은 35.8 mm입니다.

그리고 P-value뿐 아니라 **통계적 판단과 현장적 의미를 분리하여 표시**한다.

# 14. Paired t-test

**개선 전 vs 개선 후**

또는

**동일 제품의 변경 전 vs 변경 후**

# 15. ANOVA

예:

- Line A / B / C

- Supplier A / B / C
    
- Material A / B / C
    
- Temperature 20 / 30 / 40℃
    
- Operator A / B / C
    

### 결과

- Between Group Variation
    
- Within Group Variation
    
- F-statistic
    
- P-value
    

하지만 사용자에게는 통계표보다 다음을 먼저 보여준다.

> **그룹 간 평균 차이가 존재하는 것으로 판단됩니다.**

그리고

> **어느 그룹 사이에서 차이가 발생했는지 확인하려면 사후검정(Post-hoc Test)을 수행하십시오.**

# 16. Post-hoc Test

사후검정(事後檢定)은 ANOVA와 연결하여 제공한다.

지원 후보:

- Tukey HSD
    
- Bonferroni
    
- Scheffé
    
- Games-Howell
    

특히 제조 현장에서는 분산이 동일하지 않은 경우를 고려하여 **Welch ANOVA + Games-Howell** 같은 방법도 지원하는 것이 바람직하다.

결과는 다음과 같이 시각화한다.

```
A ─────── B
          │
A ───────────── C

B와 C : 유의한 차이
A와 B : 유의한 차이 없음
A와 C : 유의한 차이
```

# 20. 가장 중요한 기능: 자동 해석 엔진

본 앱의 핵심 경쟁력이다.

통계 결과를 단순히 출력하지 않고,

**Statistical Result → Manufacturing Interpretation**

으로 변환한다.

예를 들어:

### 통계 결과

```
Difference = 0.82
P-value = 0.003
95% CI = 0.31 ~ 1.33
```

### 일반 통계 프로그램

> P-value < 0.05

### 본 앱

> **판정: 두 공정의 평균에는 통계적으로 유의한 차이가 있습니다.**

> B공정의 평균이 A공정보다 약 0.82 높습니다.

> 95% 신뢰구간은 0.31~1.33입니다.

> 따라서 두 공정의 차이가 단순한 우연한 변동인지에 대해서는 유의한 차이가 있다고 판단할 수 있습니다.

그리고 별도로:

> **현장 판단:** 이 차이가 제품 규격 또는 고객 요구사항에 영향을 미치는 수준인지 추가 검토가 필요합니다.

이처럼

### Statistical Significance

**통계적 유의성(統計的 有意性)**

과

### Practical Significance

**실질적 유의성(實質的 有意性)**

을 구분한다.

# 26. 분석 결과의 3단계 설명

즉,

**쉬운 설명 → 기술적 설명 → 통계 원문**

# 49. 결론

본 프로젝트에서 **통계 알고리즘 자체는 차별화 요소가 아니다.**

차별화의 핵심은 다음 네 가지로 정의하는 것이 가장 적절하다.

### 1. 접근성(Accessibility)

통계를 잘 모르는 제조 현장 사용자도 쉽게 사용할 수 있어야 한다.

### 2. 직관성(Intuitiveness)

숫자와 통계표보다 그래프와 시각적 비교를 먼저 보여줘야 한다.

### 3. 해석성(Interpretability)

P-value를 보여주는 것에서 끝나지 않고,

> **“이 결과가 무엇을 의미하는가?”**

를 설명해야 한다.

### 4. 제조 적용성(Manufacturing Applicability)

일반적인 통계 예제가 아니라

> 공정 / 설비 / 품질 / CTQ / 생산 / 검사 / 작업자 / 조건

등 제조 현장에서 실제로 발생하는 문제를 중심으로 분석해야 한다.

따라서 이 제품의 본질은 **“Minitab의 기능을 더 쉽게 만드는 것”이 아니라, 제조 엔지니어가 통계 전문가가 아니어도 통계적 사고(Statistical Thinking)를 활용할 수 있도록 만드는 것**이다.

특히 향후 SPC, 공정능력(Capability), Pareto, 불량분석, 이상탐지(Anomaly Detection), DOE(실험계획법)까지 확장하면 단순 통계 앱이 아니라 **제조 품질·공정 데이터 분석 플랫폼**으로 발전시킬 수 있다.

이 기획을 실제 개발 단계로 가져간다면, 다음 단계에서는 **“기능 목록”보다 먼저 앱의 정보구조(IA)와 화면 흐름을 확정하는 것**을 권합니다. 특히 이 제품의 성패를 좌우하는 것은 `Analysis Navigator → Data Input → Graph → Statistical Result → 쉬운 해석 → Manufacturing Judgment`의 UX입니다.

그리고 한 가지 중요한 설계 포인트가 있습니다. **AI/LLM을 처음부터 전면에 내세우기보다는 통계 계산은 결정론적 엔진으로 고정하고, LLM은 해석·질문응답·분석 추천을 담당하도록 분리**하는 것이 좋습니다. 그래야 통계적 신뢰성과 AI의 편의성을 동시에 확보할 수 있습니다.
