# 분석 패키지 명세 #2 — 원인분석 패키지

> CASE-001(에어컨 인터뷰의 "툴 교환법")과 CASE-005(문헌)에서 공통 확인된 패턴: 불량·편차의 원인을 경험·직관으로 추정한 뒤 대응하고, 여러 후보원인 중 실제 기여도가 큰 것을 통계적으로 좁히지 않습니다. 이 패키지는 사용자가 "결과변수 + 후보원인들"만 입력하면 나머지를 자동으로 처리하여, 후보원인을 통계적 근거로 좁혀줍니다. **런타임에 AI를 호출하지 않으며, 결과검증 패키지(DELIV-PKG-SPEC-001)와 동일한 구조 패턴을 따릅니다.**

## 1. 목적 및 트리거

**트리거 조건**: 사용자가 결과변수(연속형 CTQ 또는 공정변수) 1개와 후보원인 변수 1개 이상을 업로드하고 "원인분석" 목적을 선택했을 때.

## 2. 입력 요구사항

| 항목 | 필수 여부 | 설명 |
|---|---|---|
| 결과변수(수치형) | 필수 | 원인을 찾고자 하는 CTQ 또는 공정변수 1개 열. |
| 후보원인 변수 | 필수(1개 이상) | 범주형(예: 라인/작업자/로트/설비/공급업체)과 연속형(예: 온도/압력/속도)을 모두 지원 — 타입은 자동 판별. |
| 측정 순서/타임스탬프 | 선택이지만 권장 | 결과검증 패키지와 동일하게 자기상관 체크에 사용. |

## 3. E2E 처리 흐름

```
Step 0. 데이터 인식        → 후보원인별 타입(범주형/연속형) 자동 판별, 범주형은 그룹 수 확인
Step 1. 시각화             → 범주형: 그룹별 박스플롯+개별값 점도표 / 연속형: 산점도
Step 2. 정규성·등분산 체크   → 범주형 후보원인 대상(결과검증 패키지 Step2와 동일 로직 재사용)
Step 3. 검정 자동 선택      → 아래 결정표에 따라 후보원인 타입별로 자동 확정
Step 4. 검정 실행+효과크기   → 후보원인별로 독립 실행
Step 5. 후보원인 우선순위화  → 효과크기 기준 내림차순 정렬(파레토 원리 응용)
Step 6. 다중비교 경고        → 후보원인 3개 이상 동시 검정 시 CLM-25 위험 경고
Step 7. 패키지 출력 조립     → 1~6 전체를 하나의 "원인 후보 순위표" 리포트로 통합
```

### Step 3 결정표 (결과검증 패키지 Step4 로직 재사용 + 연속형 원인 추가)

| 후보원인 타입 | 그룹 수 / 조건 | 정규성 | 선택되는 검정 | 비고 |
|---|---|---|---|---|
| 범주형 | 2그룹 | 무관(등분산검정 생략) | **Welch's t-test(기본값)** | NAV-REQ-02와 동일 원칙 — CLM-22/24 근거 |
| 범주형 | 2그룹, n<10 & 정규성 위반 | — | Mann-Whitney U | 비모수 |
| 범주형 | 3그룹 이상 | 전 그룹 p≥0.05 | Welch's ANOVA(사후 Games-Howell) | |
| 범주형 | 3그룹 이상 | 어느 그룹이든 p<0.05 | Kruskal-Wallis(사후 Dunn's test) | |
| 연속형 | — | 양쪽 변수 정규성 확보 | Pearson 상관계수 | |
| 연속형 | — | 정규성 위반 | Spearman 순위상관 | |

### Step 5 우선순위화 (효과크기 기반 랭킹) — [추론, 설계 확장]

범주형 원인은 η²(에타제곱, ANOVA/Kruskal-Wallis) 또는 Glass's delta/rank-biserial(2그룹), 연속형 원인은 상관계수 절댓값을 공통 척도로 환산해 내림차순 정렬합니다. **이 "검정 유의성+효과크기를 결합해 후보원인을 순위화"하는 방식은 Pareto 원문(SRC-135, 발생빈도 기반 80/20 원리)에는 없는 설계 확장이며, CLM-34에 [추론]으로 명시되어 있습니다.** 사용자에게는 "이 순서로 확인해보시길 권장합니다"라는 안내와 함께, 순위가 통계적 근거이지 절대적 인과관계 증명이 아니라는 문구를 함께 표시합니다.

### Step 6 다중비교 경고 (CLM-25 근거)

동시에 검정되는 후보원인이 3개 이상이면, 개별 p-value를 그대로 사용할 경우 familywise 오류율이 부풀려질 수 있다는 경고를 결과 상단에 표시합니다(시뮬레이션 근거: 3회 반복검정 시 12.5% vs 단일검정 5.0%, FND-10). 필요 시 Bonferroni 보정된 유의수준도 함께 제시합니다.

## 4. 해석 템플릿 라이브러리 (슬롯 기반)

**슬롯 정의**: `{원인명}`, `{검정명}`, `{p값}`, `{유의여부}`, `{효과크기값}`, `{효과크기등급}`, `{순위}`, `{다중비교경고}`(있음/없음)

| 유의여부 | 효과크기등급 | 다중비교경고 | 템플릿 |
|---|---|---|---|
| 유의 | 큼 | 없음 | "{순위}순위: {원인명}의 영향이 통계적으로 유의하며(p={p값}) 효과크기도 큽니다({효과크기값}). 이 원인을 최우선으로 확인·개선하는 것을 권장합니다." |
| 유의 | 중간 | 없음 | "{순위}순위: {원인명}의 영향이 통계적으로 유의합니다(p={p값}). 효과크기는 중간 수준({효과크기값})으로, 유력한 후보이지만 더 큰 효과크기를 가진 다른 순위가 있다면 그쪽을 먼저 확인하십시오." |
| 유의 | 작음 | 없음 | "{순위}순위: {원인명}은 통계적으로는 유의하지만(p={p값}) 효과크기가 작습니다({효과크기값}). 다른 상위 순위 원인을 먼저 확인한 뒤 참고하십시오." |
| 비유의 | — | 없음 | "{원인명}은 이번 데이터에서 통계적으로 유의한 영향이 확인되지 않았습니다(p={p값}). 원인이 아니라는 뜻이 아니라, 이번 표본으로는 확인하지 못했다는 뜻입니다." |
| — | — | **있음** | "⚠ 여러 후보원인을 동시에 검정했습니다. 개별 p-value만으로 판단하면 우연히 유의하게 나올 위험이 있으니({다중비교경고}), 상위 순위 원인 위주로 우선 확인하고 필요 시 보정된 기준을 함께 참고하십시오." (다른 템플릿보다 **우선 표시**) |

**[2026-09-10 추가, GAP-09 전수화]** 유의여부×효과크기등급 조합(비유의 1개 + 유의×3등급)을 전부 커버. 다중비교경고는 개별 원인 순위 템플릿과 독립적인 **접두 경고**로, 여러 후보원인 중 3개 이상이 동시 검정될 때 발동하며 각 순위별 핵심 템플릿 앞에 붙는 형태로 조립됩니다(배타적 대체가 아님) — ResultVerification/ProactiveComparison의 자기상관경고와 동일한 조립 패턴(M-INTERP-ASSEMBLE 공통 규칙).

## 5. PRISM 연동 관련 미확정 사항 (GAP-08 — DEC-009로 본 연구범위 제외)

Ian의 지시에 따라 PRISM의 기술 스택·데이터 스키마·API는 이 연구 단계에서 조사하지 않으며, Claude Code 개발 착수 시 최종 지침서·앱 폴더와 함께 직접 전달됩니다. 이 섹션은 그 시점에 채워질 placeholder입니다: (1) 후보원인 데이터(라인/작업자/설비 등)를 PRISM이 이미 보유하고 있는지 여부, (2) 원인분석 패키지가 결과검증 패키지(DELIV-PKG-SPEC-001)와 연계 실행되는 UI 흐름.

## 6. 다른 패키지에 적용할 재사용 패턴

Step 3 검정 자동선택 결정표는 결과검증 패키지(DELIV-PKG-SPEC-001) Step4와 동일한 Welch's 기본값화 로직을 그대로 재사용했습니다 — 향후 패키지 간 공통 "검정선택 엔진" 모듈로 분리 구현할 것을 제안합니다. 다중비교 경고(Step6) 로직도 후보요인이 많은 핵심요인분석 패키지에서 재사용 가능합니다.
