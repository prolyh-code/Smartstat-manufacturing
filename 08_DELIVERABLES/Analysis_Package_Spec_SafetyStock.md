# 분석 패키지 명세 #8 — 안전재고 산정 패키지

> Ian이 DEC-012로, Claude가 명시적으로 고지한 도메인 불일치 위험(품질/공정 통계 vs 재고관리)을 인지한 상태에서 착수를 직접 결정한 패키지입니다. 부품·자재의 수요 변동성을 바탕으로 안전재고와 재주문점을 산출합니다. **런타임에 AI를 호출하지 않습니다.**
>
> **[근거등급 고지 — 중요]** 이 패키지는 다른 7개 패키지와 두 가지 점에서 다릅니다. (1) 통계 대상이 CTQ·품질특성이 아니라 수요·재고라는 별개 도메인입니다. (2) 뒷받침하는 문헌이 실무 컨설팅 자료 2건(SRC-151/152)뿐이며, 재고관리 전문 교과서 수준의 검증은 거치지 않았습니다. 근거등급을 medium/low-medium으로 낮게 표시한 이유입니다. Ian 또는 재고관리 담당자의 검토를 통계 담당자 검토보다 더 우선적으로 권장합니다.

## 1. 목적 및 트리거

**트리거 조건**: 사용자가 "재고/발주 기준 설정" 목적을 선택하고, 자재·부품별 과거 수요(및 가능하면 리드타임) 이력을 업로드했을 때. CASE-003(문헌)에서 확인된 "수요변동 대응 재고기준 설정" 니즈에 대응합니다.

## 2. 입력 요구사항

| 항목 | 필수 여부 | 설명 |
|---|---|---|
| 자재/부품 식별자 | 필수 | 어떤 품목인지. |
| 기간별 수요(수치형, 시계열) | 필수 | 일/주/월 단위 과거 수요량. |
| 리드타임(수치형) | 권장 | 발주부터 입고까지 걸리는 기간. 없으면 평균 리드타임만 사용자 입력값으로 대체(변동성 반영 불가 — Step 2에서 자동 판단). |
| 목표 서비스수준(%) | 권장 | 없으면 업계 관행값(95%)을 기본값으로 제시하고 확인질문으로 전환(M-DATA-PROFILE의 "항상 확인" 원칙 적용, DEC-011). |

## 3. E2E 처리 흐름 (결정론적, 사용자 개입 없이 전부 자동 실행)

```
Step 0. 데이터 인식(M-DATA-PROFILE)         → 수요 이력 개수·리드타임 데이터 유무 확인, 확인질문 전환
Step 1. 수요/리드타임 통계 산출(M-INVENTORY-DEMANDSTATS) → 평균·표준편차 계산
Step 2. 계산방식 자동선택(M-INVENTORY-METHODSELECT) → 리드타임 변동 데이터 유무로 2종 중 선택
Step 3. 안전재고 산출(M-INVENTORY-SAFETYSTOCK) → 서비스수준(Z-score) 반영
Step 4. 재주문점 산출(M-INVENTORY-REORDERPOINT) → 안전재고 + 리드타임 중 평균수요
Step 5. 해석 조립(M-INTERP-ASSEMBLE)         → 아래 §4 템플릿 적용
Step 6. 안전 폴백(M-SAFETY-FALLBACK)
```

### Step 2 결정표 ([SRC-151/CLM-45 근거])

| 리드타임 변동 데이터 | 선택 방식 | 공식 |
|---|---|---|
| 없음(리드타임 고정값만 있음) | 수요 변동성만 반영 | 안전재고 = Z × σ수요 × √리드타임 |
| 있음(리드타임도 매번 다름) | 수요+리드타임 변동성 독립 반영 | 안전재고 = Z × √(리드타임×σ수요² + 평균수요²×σ리드타임²) |

[근거: SRC-151의 Method 3/5. 수요·리드타임 간 상관관계(Method 6)는 이번 1차 명세에서 제외 — 데이터 가용성이 낮고 드문 사례로 분류됨]

### Step 3 서비스수준 → Z값 환산 (표준정규분포 기준)

| 목표 서비스수준 | Z값 |
|---|---|
| 90% | 1.28 |
| 95% | 1.65 |
| 99% | 2.33 |

[통계 통설 — 표준정규분포 누적확률표에서 도출되는 값으로 별도 출처 표기 불필요한 수준의 공지 지식이나, 정확성을 위해 재고관리 문헌(SRC-151)의 관행값과 대조 확인함. **[2026-09-10 추가교차검증]** SRC-154(NC State)는 90%에 대해 1.29를 사용해 SRC-151(1.28)과 소수점 둘째자리 표기가 다르나(CLM-48), 둘 다 표준정규분포 0.90분위수(정확값 약 1.2816)를 반올림한 것으로 방법론적 불일치가 아님을 확인 — 표는 기존 1.28을 유지]

## 4. 해석 템플릿 라이브러리 (슬롯 기반, GAP-09 방법론 적용)

**슬롯 정의**: `{품목명}`, `{안전재고}`, `{재주문점}`, `{서비스수준}`, `{계산방식}`(수요만/수요+리드타임), `{리드타임데이터부족경고}`(있음/없음), `{수요이력부족경고}`(있음/없음)

**슬롯 유형 판정**: 계산방식(2종)은 **배타적 핵심분류**(Step 2에서 자동으로 둘 중 하나만 선택됨), 리드타임데이터부족경고·수요이력부족경고는 **접두 경고**(핵심분류와 독립, 항상 먼저 표시).

| 계산방식 | 템플릿 |
|---|---|
| 수요 변동성만 반영 | "{품목명}의 안전재고는 약 {안전재고}, 재주문점은 약 {재주문점}으로 계산되었습니다(목표 서비스수준 {서비스수준}%, 수요 변동성 기준). 리드타임이 매번 달라지는 데이터가 없어 리드타임은 고정값으로 가정했습니다 — 리드타임 변동 이력을 확보하면 더 정확한 값을 얻을 수 있습니다." |
| 수요+리드타임 독립 반영 | "{품목명}의 안전재고는 약 {안전재고}, 재주문점은 약 {재주문점}으로 계산되었습니다(목표 서비스수준 {서비스수준}%, 수요와 리드타임 변동성을 모두 반영). 재고가 이 수준 아래로 내려가면 발주하는 것을 권장합니다." |
| — (리드타임데이터부족경고 **있음**) | "참고: 리드타임 변동 이력이 없어 고정값으로 계산했습니다. 실제로는 리드타임도 매번 달라질 수 있으므로, 이 수치는 다소 낙관적(과소추정)일 수 있습니다." (핵심분류 템플릿 뒤에 이어 붙임 — 수요 변동성만 반영 방식에서만 발생) |
| — (수요이력부족경고 **있음**, 데이터 12개월 미만) | "⚠ 수요 이력이 아직 짧아({개월수}개월) 계절성이나 특이 수요 패턴을 충분히 반영하지 못했을 수 있습니다. 데이터가 더 쌓인 후 재확인을 권장합니다." (다른 템플릿보다 **우선 표시**) |
| (매칭 실패 시 기본값) | "이 조합에 대한 표준 해석 문구가 아직 준비되지 않았습니다. 수치 결과(안전재고={안전재고}, 재주문점={재주문점})를 직접 확인하시거나 재고관리 담당자에게 문의하십시오." — **필수 포함** |

**전수화 확인**: 계산방식 2종(배타적) × 수요이력부족경고 2종(접두) × 리드타임데이터부족경고 2종(접두, 계산방식이 "수요만"일 때만 발생하는 조건부 접두) — 핵심분류 2개+접두경고 2개+폴백 1개, 총 5개 구성요소로 조합을 전부 커버.

## 5. PRISM 연동 관련 미확정 사항 (GAP-08 — DEC-009로 본 연구범위 제외)

Ian의 지시에 따라 PRISM의 기술 스택·데이터 스키마·API는 이 연구 단계에서 조사하지 않습니다. 특히 이 패키지는 PRISM이 이미 자재별 수요·발주 이력을 관리하는 ERP/MRP 시스템과 연동되어 있는지, 아니면 이 Add-on이 완전히 독립적으로 데이터를 입력받아야 하는지가 실용성에 큰 영향을 미치므로, GAP-08 해소 시점에 반드시 확인해야 할 항목입니다.

## 6. 미해결 항목 (GAP-11 잔여, 근거 보강 필요)

- 이 패키지는 재고관리 전문 교과서(예: 표준 SCM/OM 교재)를 아직 조사하지 않았습니다 — 실무 컨설팅 자료(SRC-151/152/154) 3건 수준의 근거만으로 설계되었다는 한계를 계속 명시해야 합니다. **[2026-09-10 부분 보강]** SRC-154(NC State, 대학 SCM 연구기관)를 추가로 확보해 Z값 환산표를 교차검증했으나(CLM-48), 이는 "실무자료 상호검증"이지 "교과서 수준 검증"과는 여전히 다릅니다 — 근거등급을 상향 조정하지 않았습니다.
- 수요·리드타임 상관관계 반영 방식(Method 6)은 이번 범위에서 제외했으나, 실제 제조현장에서 수요 급증기에 리드타임도 함께 길어지는 경우가 흔하다면 과소추정 위험이 있을 수 있습니다 — 향후 실데이터 확보 시 재검토 필요.
- 서비스수준 90/95/99% 외의 값(예: 92%)에 대한 Z값 세분화 테이블은 이번 1차 명세에서 생략했습니다 — 개발 단계에서 표준정규분포 역함수 계산으로 대체 가능.

## 7. 다른 패키지에 적용할 재사용 패턴

M-DATA-PROFILE(자동판별 시 항상 확인질문 전환, DEC-011)·M-INTERP-ASSEMBLE·M-SAFETY-FALLBACK은 기존 패키지와 동일하게 재사용됩니다. 이 패키지는 G9의 원래 5대 주제(MSA·원인분석·핵심요인분석·결과검증·유지관리)에 속하지 않는 **최초의 도메인 이탈 패키지**이므로, 향후 유사한 비(非)품질통계 확장 요청이 있을 때 "도메인 불일치를 명시적으로 고지 → Ian 결정 → 근거등급을 낮게 표시하고 진행" 절차의 선례로 참고할 수 있습니다.
