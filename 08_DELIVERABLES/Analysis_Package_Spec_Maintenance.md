# 분석 패키지 명세 #5 — 유지관리 패키지

> CASE-001("재발시 또 조정 반복")과 CASE-008(문헌)에서 공통 확인된 패턴: 개선 직후에는 좋아지다가 공식적 관리계획 없이 시간이 지나며 원상태로 돌아가는 경우가 널리 보고됩니다(CLM-20). 결과검증 패키지(DELIV-PKG-SPEC-001)로 개선을 확인한 이후, 이 패키지는 개선효과가 실제로 유지되는지 자동으로 추적합니다. **런타임에 AI를 호출하지 않습니다.**

## 1. 목적 및 트리거

**트리거 조건**: 사용자가 "개선 후 유지관리/추적" 목적을 선택하고 개선 후 시계열 측정값을 업로드했을 때. [추론, 향후 통합설계 과제] 결과검증 패키지 완료 후 "이후 데이터를 계속 추적하시겠습니까?"라는 형태로 자동 연계 제안될 수 있습니다 — 구체적 연계 UI는 GAP-08 해소 후 확정.

## 2. 입력 요구사항

| 항목 | 필수 여부 | 설명 |
|---|---|---|
| 측정값(수치형) | 필수 | 추적 대상 CTQ 또는 공정변수. |
| 측정 순서/타임스탬프 | **필수** | 다른 패키지와 달리 이 패키지는 시계열 순서가 핵심이므로 선택이 아닌 필수. |
| 개선 시점 표시 | 권장 | 관리한계선을 개선 후 데이터로만 재기준선(re-baseline)하기 위해 필요. |

## 3. E2E 처리 흐름

```
Step 0. 데이터 인식        → 개선 후 누적 데이터 개수 확인(관리도 신뢰성 위해 최소 20~25점 권장)
Step 1. 관리도 자동생성     → I-MR(개별값-이동범위) 관리도, 개선 후 데이터로 관리한계 재기준선
Step 2. 이상감지 규칙 적용   → Western Electric Rules 4종을 **각각 독립적으로** 전체 데이터에 적용(하나의 규칙만 골라내는 것이 아니라, 4개 규칙 각각에 대해 위반 여부를 개별 판정)
Step 3. 패키지 출력 조립     → 관리도 + **위반된 규칙 전부의 목록(0~4개, 동시에 여러 개 가능)** + 각 위반에 대응하는 해석을 하나의 리포트로 통합, 위반 시 알림
```

**[2026-09-10 수정, GAP-09 전수화]** 이전 버전에서는 "위반규칙" 슬롯을 Rule1~4 중 하나를 고르는 단일 배타적 분류처럼 다뤘으나, Western Electric Rules는 원래 여러 규칙이 **동시에** 위반될 수 있도록 설계된 체계입니다(예: 급격한 이상값(Rule1)과 동시에 전반적 수준 이동(Rule4)이 함께 나타나는 경우가 흔함). 따라서 Step 2~3을 "4개 규칙 각각을 독립 판정 → 위반된 것 전부를 목록으로 모아 조립"하는 구조로 재설계했습니다. §4의 해석 템플릿도 이에 맞춰 "규칙별 개별 템플릿을 위반된 것만 이어 붙이는" 방식으로 수정합니다.

### Step 0 데이터 부족 경고

누적 데이터가 20점 미만이면 "데이터가 아직 충분하지 않아({개수}점) 관리한계선의 신뢰도가 낮을 수 있습니다. 최소 20~25점 누적 후 재확인을 권장합니다"라는 경고를 표시하되, 계산 자체는 진행합니다.

### Step 2 결정표 (Western Electric Rules, [SRC-136 근거])

| 규칙 | 조건 | 의미 |
|---|---|---|
| Rule 1 | 1점이 관리상한(UCL) 초과 또는 관리하한(LCL) 미만 | 급격한 이상값 발생 |
| Rule 2 | 연속 3점 중 2점이 같은 방향으로 2-시그마 구간 밖 | 이상 신호(중간 강도) |
| Rule 3 | 연속 5점 중 4점이 같은 방향으로 1-시그마 구간 밖 | **서서히 원래 수준으로 돌아가는 경향(재발 조짐) — 유지관리 패키지의 핵심 탐지 대상** |
| Rule 4 | 연속 8점이 중심선 한쪽에 전부 위치 | 지속적 수준 이동(공정 자체가 바뀜) |

## 4. 해석 템플릿 라이브러리 (슬롯 기반, **[2026-09-10 재설계] 목록형 조립 — 단일 배타적 분류 아님**)

**슬롯 정의**: `{위반시점}`, `{데이터부족경고}`(있음/없음)

**조립 규칙**: 최종 출력 = [데이터부족경고(있으면, 항상 최우선 표시)] + [위반된 규칙 각각의 템플릿을 발생한 것만 순서대로 나열, Rule1→Rule2→Rule3→Rule4 순] + [아무 규칙도 위반되지 않았으면 "이상 없음" 템플릿 1개만 단독 표시]. 즉 규칙별 템플릿은 서로 배타적이지 않고 **동시에 여러 개가 함께 출력될 수 있는 목록**입니다 — "없음" 템플릿은 4개 규칙이 전부 위반되지 않았을 때만 사용하는 별도 상태이며, 단 1개라도 위반되면 "없음" 템플릿은 표시하지 않습니다.

| 상태 | 템플릿 |
|---|---|
| 4개 규칙 전부 위반 없음 | "현재까지 이상 신호가 감지되지 않았습니다. 개선효과가 안정적으로 유지되고 있는 것으로 보입니다." (다른 어떤 규칙 템플릿과도 함께 나오지 않음) |
| Rule 1 위반 | "⚠ {위반시점} 시점에서 관리한계를 벗어난 급격한 이상값이 발생했습니다. 해당 시점의 특이사항(자재·설비·작업자 변경 등)을 확인하십시오." |
| Rule 2 위반 | "⚠ {위반시점} 부근에서 연속된 측정값 중 다수가 평소보다 한쪽으로 크게 치우쳐 있습니다(중간 강도 이상 신호). 아직 급격한 이상값은 아니지만, 공정이 서서히 한쪽으로 쏠리기 시작했을 가능성이 있으니 다음 몇 개 데이터를 주의 깊게 지켜보십시오." |
| Rule 3 위반 | "⚠ {위반시점} 부근에서 측정값이 서서히 이전 수준으로 돌아가는 경향(재발 조짐)이 감지되었습니다. 개선 조치가 느슨해지고 있지 않은지 현장을 재점검하십시오." |
| Rule 4 위반 | "⚠ {위반시점} 이후 공정의 전반적인 수준이 이동한 것으로 보입니다. 의도된 추가 개선인지, 의도치 않은 이동인지 확인하십시오." |
| **2개 이상 규칙 동시 위반** | 위 개별 규칙 템플릿을 Rule1→2→3→4 순서로 전부 이어 붙여 표시 + 목록 맨 앞에 "⚠ 여러 이상 신호가 동시에 감지되었습니다({위반규칙목록}). 아래 각 항목을 함께 확인하십시오." 안내문 1줄 추가 |
| 데이터부족경고 있음 | "⚠ 누적 데이터가 아직 부족해({데이터부족경고}) 아래 판정의 신뢰도가 낮을 수 있습니다. 데이터가 더 쌓인 후 재확인하십시오." — 위반규칙 목록과 별개 차원의 **접두 경고**이므로 위 어떤 상태와도 함께 나올 수 있음(항상 가장 먼저 표시) |
| (규칙 판정 자체가 실패한 경우의 기본값) | "이 조합에 대한 표준 해석 문구가 아직 준비되지 않았습니다. 관리도를 직접 확인하시거나 통계 담당자에게 문의하십시오." — **필수 포함** |

**전수화 확인**: 4개 규칙 각각 위반/비위반 2가지이므로 이론상 2⁴=16가지 조합이 가능하지만, 목록형 조립 방식을 택했기 때문에 "규칙별 템플릿 5개(없음 1개+Rule1~4 4개) + 동시위반 안내문 1개 + 데이터부족 접두경고 1개"만 준비하면 16가지 조합을 전부 커버합니다(각 조합은 이 7개 구성요소의 조합으로 기계적으로 생성되므로, 조합 수만큼 템플릿을 따로 쓸 필요가 없음). 이는 GAP-09가 우려하는 "AI 없이 모든 분기를 커버하지 못하는 위험"에 대한 구조적 해법입니다 — 배타적 분류형 슬롯(유의여부×효과크기 등)은 분류마다 템플릿이 필요하지만, 목록형 슬롯(위반 규칙)은 구성요소만 준비하면 조합을 자동으로 커버합니다.

## 5. PRISM 연동 관련 미확정 사항 (GAP-08 — DEC-009로 본 연구범위 제외)

Ian의 지시에 따라 PRISM의 기술 스택·데이터 스키마·API는 이 연구 단계에서 조사하지 않으며, Claude Code 개발 착수 시 최종 지침서·앱 폴더와 함께 직접 전달됩니다. 특히 이 패키지는 "새 데이터가 들어올 때마다 자동으로 재검사하여 알림을 보내는" 상시 모니터링 방식이 이상적이나, PRISM의 데이터 수집 주기·알림 체계를 알아야 설계 가능하므로 지금은 "사용자가 누적 데이터를 다시 업로드하면 재검사"하는 수동 방식으로 가정합니다.

## 6. 다른 패키지에 적용할 재사용 패턴

이 패키지로 G9의 5대 Case Library 주제(결과검증·원인분석·핵심요인분석·MSA·유지관리)에 대응하는 분석 패키지 명세가 모두 1차 작성되었습니다. Rule 3(서서히 드리프트) 탐지 로직은 결과검증 패키지의 자기상관 체크(Step 3)와 개념적으로 연결되며(둘 다 "시간에 따른 서서히 변하는 경향"을 다룸), 향후 공통 "시계열 이상탐지" 모듈로 통합할 수 있습니다.
