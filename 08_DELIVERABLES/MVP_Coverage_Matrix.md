# 분석 패키지 범위 대 Case Library 커버리지 매트릭스

> **[v2.0 갱신 고지]** v1.0(2026-09-10 초안)은 기획서의 "Phase1(MVP)/Phase2/Phase3" 기능 목록을 기준으로 작성되었고, 그 시점에는 분석 패키지가 하나도 완성되지 않은 상태였습니다. 이후 DEC-008(PRISM Add-on/무AI 전환)과 DEC-010(모듈 카탈로그·분석 패키지 방식 채택)을 거치면서, "개별 통계 도구가 Phase1에 있는가"라는 원래 질문 자체가 **"현장 목적별로 여러 기법을 자동 연계하는 분석 패키지가 존재하는가"**로 바뀌었습니다. v2.0은 8개 완성된 분석 패키지를 기준으로 이 질문에 다시 답합니다. **Phase1/2/3 로드맵 배치 자체는 여전히 Ian의 결정 사항이며, 이 문서는 "패키지가 설계상 존재하는가"만 답합니다.**

## 결론부터

**8개 사례 전부가 이제 대응하는 분석 패키지를 갖고 있습니다** — v1.0 시점의 "완전 커버 0/8"에서 크게 개선되었습니다. 다만 이것이 "8개 사례가 실전에서 완벽히 해결된다"는 뜻은 아닙니다. 남은 격차는 성격이 달라졌습니다: v1.0은 "그 기법 자체가 Phase1 범위 밖"이라는 **설계 공백**이었지만, 지금은 (1) 그 패키지가 PRISM과 실제로 통합되는 방식(GAP-08, 의도적 미결), (2) 신뢰성·안전재고 2개 패키지의 근거등급이 낮다는 점(GAP-10/11 잔여), (3) 해석 템플릿 문구가 실사용자에게 검증되지 않았다는 점(GAP-02/05)이라는 **검증 공백**으로 바뀌었습니다. 이는 v1.0이 지적한 구조적 공백 2건(가정확인 도구 부재, MSA 부재)이 실제로 해소되었음을 의미합니다 — 8개 패키지 전부 E2E 흐름에 가정확인 모듈을 검정 실행보다 먼저 배치하도록 설계되었고, MSA는 독립 패키지(DELIV-PKG-SPEC-004)로 완결되었습니다.

## v1.0이 지적한 구조적 공백 2건 — 현재 상태 재평가

### FND-11 / CLM-28 — "Phase 1은 가정 확인 도구 없이 검정 도구만 제공한다" → **해소됨**

v1.0 시점에는 기획서의 Phase1 범위에 정규성·등분산 검정이 아예 없었습니다. 지금은 8개 분석 패키지 **전부**가 E2E 처리흐름에서 가정확인 모듈(M-ASSUMP-NORMALITY 등)을 검정 실행 모듈보다 항상 먼저 배치하도록 설계되어 있습니다(Analysis_Module_Library_and_Composition_Rules.md §2.3). 이는 원래 NAV-REQ-01(정규성·등분산 선확인)이 요구했던 것을 구조적으로 만족합니다. **남은 것은 "이것이 Phase1/2/3 중 어디에 배치되는가"라는 로드맵 결정뿐이며, "그 기능 자체가 없다"는 문제는 더 이상 존재하지 않습니다.**

### FND-11 / CLM-29 — "MSA 부재가 Phase1 전체의 전제를 흔든다" → **해소됨**

CASE-004(MSA)는 이제 독립된 완결 패키지(DELIV-PKG-SPEC-004)입니다. spc-profile.md의 변동위계 원칙(측정시스템이 가장 먼저 검증되어야 함)을 만족하는 %GRR/NDC 판정 로직이 갖춰져 있습니다. 다만 v1.0이 우려했던 "다른 패키지 결과에 자동으로 MSA 불량 경고를 연동"하는 기능은 아직 없습니다 — 이는 Analysis_Module_Library_and_Composition_Rules.md §8에서 "패키지 간 상태공유 메커니즘 필요, GAP-08 해소 후 구현 가능"으로 이미 식별되어 있는 별개의 잔여 항목입니다.

## 종합 판단 [추론]

v1.0의 결론("불충분하다, 다만 의도된 단계적 축소의 결과")은 더 이상 유효하지 않습니다. 설계 수준에서는 8개 사례 모두 대응 패키지를 갖추고, 구조적 공백 2건도 해소되었습니다. 지금 남은 질문은 성격이 다릅니다: (1) 이 8개 패키지를 실제로 언제·어떤 순서로 배포할지(Phase 로드맵, Ian 결정), (2) PRISM과의 기술적 통합(GAP-08), (3) 해석 템플릿 문구·Navigator 문구가 실사용자에게 실제로 통하는지(GAP-02/05, 프로토타입 필요), (4) 신뢰성·안전재고 2개 패키지의 근거등급을 더 보강할지(GAP-10/11, 우선순위 낮음)입니다. 이는 "무엇을 만들 것인가"에서 "어떻게 검증하고 배포할 것인가"로 질문이 이동했다는 뜻이며, 연구 단계에서 개발/검증 단계로 넘어갈 준비가 되었다는 신호로 해석할 수 있습니다.

## 한계

- 이 매트릭스는 8개 패키지의 "설계상 존재·구조적 완전성"만 확인했습니다 — 실제 코드 구현(Claude Code 개발단계)이나 실사용자 검증(GAP-02/05)을 대체하지 않습니다.
- CASE-002~008(문헌 7건)의 정성적 대응관계에 기반하며, 국내 사내 실제 사례로 검증된 것은 CASE-001(에어컨, 1건)뿐이라는 v1.0의 한계는 그대로 유지됩니다.
- 신뢰성·안전재고 패키지의 "완성도" 평가는 다른 6개 패키지보다 낮은 근거등급을 전제로 한 것이며, 동일 선상에서 비교하지 않도록 표에 "1차 명세"로 별도 표기했습니다.
