# 분석 패키지 명세 #6 — 예방적 비교 패키지

> 이 명세는 `Analysis_Module_Library_and_Composition_Rules.md`의 모듈 카탈로그를 사용해 **신규 모듈 추가 없이** 조합(compose)으로 작성되었습니다 — 모듈/조합규칙 체계가 실제로 새 패키지 제작에 쓰일 수 있음을 보여주는 시범사례입니다. CASE-001 인터뷰에서 확인된 FND-08("현재 비교·검증은 문제가 명백해진 뒤에만 반응적으로 발생하고 사전 예방적 비교는 없다")을 직접 해소합니다.

## 1. 목적 및 트리거

결과검증 패키지(DELIV-PKG-SPEC-001)와 통계 로직은 동일하지만 시점과 의도가 다릅니다: 결과검증은 "조치를 이미 취했고 그 효과를 사후 확인"하는 반응적(reactive) 목적인 반면, 이 패키지는 "아직 문제가 드러나지 않은 상태에서 현재 데이터를 기준선과 비교해 이상 징후를 조기에 포착"하는 예방적(proactive) 목적입니다.

**트리거 조건**: 사용자가 Navigator에서 "아직 특별한 문제는 없지만, 최근 상태가 평소와 다른지 미리 점검하고 싶다"를 선택하고, 현재(최근) 데이터 + 비교기준(과거 안정기간 데이터 또는 규격·목표값)을 업로드했을 때.

## 2. 입력 요구사항

결과검증 패키지(DELIV-PKG-SPEC-001 §2)와 동일한 표를 그대로 사용합니다 — 단, "개선 전/후" 그룹 명칭을 "기준(baseline)/현재(current)"로 바꿔 해석합니다.

## 3. 모듈 조합 (레시피)

```
RECIPE ProactiveComparison
TRIGGER: 현재 데이터 + 비교기준 데이터 업로드 + "예방적 비교" 선택
FLOW:
  M-DATA-PROFILE
  → M-VIZ-HISTBOX
  → M-ASSUMP-NORMALITY
  → BRANCH(시계열 정보 있음?)
      YES → M-VIZ-RUNCHART → M-ASSUMP-AUTOCORR [우선순위: 최상단 경고]
      NO  → skip
  → M-TESTSELECT-COMPARE
  → M-EFFECT-COMPARE
  → M-INTERP-ASSEMBLE (§4의 예방적 프레이밍 템플릿 사용)
  → M-SAFETY-FALLBACK
  NEXT: 유의한 차이+효과크기 큼 발견 시 → RootCause 패키지 실행을 추천(자동실행 아님, 사용자 확인 후 진행)
```

사용된 모듈은 전부 카탈로그에 이미 있으며, **신규 모듈은 0개**입니다. 통계 실행 로직은 결과검증 패키지와 완전히 동일하고, 트리거 의도와 해석 문구만 다릅니다.

## 4. 해석 템플릿 라이브러리 (예방적 프레이밍 — 슬롯은 결과검증 패키지와 동일, 문구만 다름)

| 유의여부 | 효과크기등급 | 템플릿 |
|---|---|---|
| 비유의 | — | "현재 데이터는 기준과 통계적으로 다르지 않습니다(p={p값}). 안정적으로 유지되고 있는 것으로 보입니다." |
| 유의 | 작음 | "기준과의 차이가 통계적으로 감지되기 시작했습니다(p={p값}, 효과크기={효과크기값}은 아직 작음). 지금 단계에서는 계속 관찰하는 것을 권장합니다." |
| 유의 | 중간 | "기준과의 차이가 통계적으로 유의하며(p={p값}), 효과크기도 중간 수준({효과크기값})으로 커지고 있습니다. 아직 뚜렷한 문제 단계는 아니지만, 다음 확인 주기에서도 같은 경향이 이어지는지 주의 깊게 관찰하는 것을 권장합니다." |
| 유의 | 큼 | "⚠ 기준과 뚜렷한 차이가 감지되었습니다(p={p값}, 효과크기={효과크기값}). 문제가 커지기 전에 원인분석 패키지로 후보원인을 확인하는 것을 권장합니다." |
| — | 자기상관경고 | (결과검증 패키지 §4의 자기상관 경고 템플릿을 그대로 재사용) |
| (매칭 실패 시 기본값) | | M-SAFETY-FALLBACK 표준 문구 그대로 사용 — "이 조합에 대한 표준 해석 문구가 아직 준비되지 않았습니다. 수치 결과를 직접 확인하시거나 통계 담당자에게 문의하십시오." |

**[2026-09-10 추가, GAP-09 전수화]** 유의여부×효과크기등급 조합을 전부 커버(비유의는 효과크기 무관 1개 템플릿, 유의는 작음/중간/큼 3개 템플릿). NEXT 체이닝(§6)은 "유의+큼"일 때만 원인분석 패키지 추천을 트리거하도록 유지하며, "유의+중간"은 아직 추천 트리거 대상이 아닙니다 — 중간 단계에서 곧바로 다른 패키지 실행을 권하면 사용자에게 과도한 조치를 유도할 위험이 있다는 판단(추론)에 따른 것으로, 실사용자 검증 전까지는 임계값을 "큼"으로 보수적으로 유지합니다.

## 5. PRISM 연동 관련 미확정 사항 (GAP-08 — DEC-009로 본 연구범위 제외)

결과검증 패키지와 동일하게 PRISM 기술스택·연동방식은 이 연구단계에서 다루지 않습니다. 추가로: 이 패키지는 "정기적으로 반복 실행"(예: 매주 최근 로트로 자동 재실행)되는 것이 이상적이나, 이는 PRISM의 데이터 수집 주기·스케줄링 기능을 알아야 설계 가능하므로 지금은 사용자가 수동으로 재실행하는 것으로 가정합니다.

## 6. 재사용 패턴 및 패키지 체이닝

이 명세는 모듈 카탈로그의 "카탈로그 재사용도 100%" 사례입니다(`Analysis_Module_Library_and_Composition_Rules.md` §8 참조). 또한 §3의 `NEXT` 필드로 **패키지 체이닝**(한 패키지의 결과가 다른 패키지 실행을 추천)을 처음 도입했습니다 — 자동 실행이 아니라 추천이며, 최종 실행 여부는 항상 사용자가 결정합니다(무AI 원칙 — 자동으로 연쇄 실행하면 사용자가 무슨 일이 일어났는지 통제·추적하기 어려워지므로 금지).
