# Executive Brief — PRISM 통계분석 Add-on

> 이전(v1.0) 실행요약을 대체합니다. 상세 근거는 `Final_Report.md`를 참조하십시오.

## 결론 먼저

이 연구의 산출물은 **PRISM(기존 CTQ 자동분석 앱)에 추가할 통계분석 Add-on**의 개발 지침서입니다 — 독립 앱이 아니며, **런타임에 AI가 없습니다**. Navigator 중심 설계 방향은 **조건부로 채택 가능**합니다. 현장 인터뷰와 통계 시뮬레이션 모두 "사용자가 도구를 몰라서가 아니라, 이 상황이 분석 대상이라는 것 자체를 인식하지 못해서" 문제가 생긴다는 것을 보여주었고, 이에 따라 Navigator는 통계 용어를 전혀 노출하지 않는 **"스무고개" 방식 상황질문 결정트리**로 재설계되었습니다. 무AI 제약에 대응해, 여러 통계기법이 자동으로 이어지는 **"분석 패키지"** 8종을 재사용 가능한 **원자 모듈 카탈로그(~29개)**로 조합했고, 각 패키지의 해석 템플릿이 가능한 모든 결과 조합을 빠짐없이 커버하는지(무AI 환경의 필수 안전망) 구조적으로 확인했습니다.

## 지금 내릴 수 있는 결정

- 핵심가치 가설(상황 인식 우선), 무AI 아키텍처, 8개 분석 패키지(모듈 조합 방식)를 연구 출발점으로 채택하고, 아래 요구사항을 Phase1 설계에 반영하는 결정은 지금 내릴 수 있습니다.
  1. Welch's t-test를 기본값으로(NAV-REQ-02) — Phase1 범위 변경 필요, 여전히 Ian 결정 대기.
  2. "시간순 연속 데이터인가?" 질문을 Navigator 진입부에 추가(NAV-REQ-04) — v2에 반영 완료.
  3. 가정 확인(정규성·등분산·독립성) 순서를 검정 실행보다 앞으로(NAV-REQ-01) — 8개 패키지 전부 반영 완료.
  4. 6개 핵심 패키지(품질통계, 구조적 완전성 확인됨)와 2개 확장 패키지(신뢰성·안전재고, 근거등급 낮음)를 Phase1/2/3 중 어디에 배치할지.

## 근거와 유효 범위

- 실제 현장 인터뷰 1건(CASE-001, 에어컨 공정) + 산업공통 문헌사례 7건 + 신뢰성/안전재고 문헌 6건(SRC-147~152) + Navigator 위험에 대한 몬테카를로 시뮬레이션(합성데이터, 재현가능) + Navigator v2 셀프 드라이런(9개 시나리오).
- 표본이 1건·1인이므로 타 제품군(냉장고·세탁기·조리기기)으로 일반화할 수 없습니다.
- 신뢰성·안전재고 2개 패키지는 문헌조사 1라운드 수준이며, 안전재고는 품질통계와 도메인 자체가 다릅니다(Ian이 이 위험을 인지하고 착수를 직접 결정).

## 핵심 불확실성 및 잔여 리스크

- Navigator 위험 시뮬레이션은 **합성데이터** 기준입니다. 실제 CTQ 데이터에서 자기상관·분산비가 얼마나 되는지는 아직 실측하지 않았습니다.
- 독립 통계전문가 리뷰가 `waived` 상태입니다(DEC-006) — Claude 자체검토가 대체 통제수단입니다.
- 실사용자 검증(GAP-01,02,05)은 여전히 미착수 — 해석 템플릿·Navigator 문구가 실제로 오해석을 유발하지 않는지는 프로토타입이 있어야 확인 가능합니다.
- PRISM과의 기술적 통합 방식(GAP-08)은 의도적으로 이 연구범위 밖입니다 — Claude Code 개발 착수 시 확정.
- 신뢰성 패키지의 비용비 기반 교체주기 산출, 안전재고 패키지의 재고관리 교과서급 근거는 아직 보강되지 않았습니다(GAP-10/11 잔여).

## 보류된 결정

- MVP 최종 기능범위 확정(8개 패키지의 Phase 배치 포함), Navigator 세부 UI 문구, Case Library 콘텐츠 최종안, PRISM 통합 세부설계 — 모두 프로토타입 단계 또는 Claude Code 개발 착수 이후로 보류.

## 금지된 결론

- "본 Add-on이 기존 방식보다 우수하다"는 정량적 주장 금지.
- "사용자 판단정확도가 실제로 향상되었다"는 효과성 주장 금지(실증 전).
- "제조 현장 전반의 니즈를 파악했다"는 주장 금지(표본 1건).
- 시뮬레이션 수치(예: 자기상관 1종오류율 63.8%)를 "실제 현장 수치"로 제시하는 것 금지.
- "PRISM과의 통합까지 설계했다"는 주장 금지(GAP-08은 의도적 범위 밖).
- "8개 패키지 모두 동일한 근거등급"이라는 주장 금지(신뢰성·안전재고는 근거가 얕음).
- "해석 템플릿 문구가 실사용자에게 검증되었다"는 주장 금지(GAP-09는 구조적 완전성만 확인).
