# 분석 패키지 명세 #1 — 개선 결과 검증 패키지

> 이 문서는 "PRISM 통계분석 Add-on"에 포함될 첫 번째 **분석 패키지**의 개발 지침서입니다. 사용자가 개별 통계기법을 하나씩 선택하지 않아도, "개선 전후를 비교해서 정말 좋아진 게 맞는지 확인하고 싶다"는 하나의 현장 목적을 입력하면 시각화→가정확인→검정선택→검정실행→효과크기→해석까지 **E2E로 자동 제공**됩니다. **런타임에 AI를 호출하지 않으며, 모든 분기와 해석 문구는 이 문서에 정의된 결정론적 규칙과 템플릿으로만 동작합니다.** 이 패키지는 향후 "원인분석 패키지"·"핵심요인분석 패키지" 등 다른 패키지를 만들 때 따라야 할 구조 패턴의 기준(reference)이기도 합니다.

## 1. 목적 및 트리거

CASE-001(에어컨 인터뷰)·CASE-007(문헌)에서 공통 확인된 패턴: 개선 조치(툴 교체, 파라미터 조정) 후 "몇 개 조립해보고 괜찮은 것 같으면" 주관적으로 확정하고, 확인런(confirmation run)이나 통계적 검정 없이 종료합니다. 이 패키지는 사용자가 "개선 전/후 데이터"만 입력하면 나머지를 전부 자동으로 처리하여, 주관적 판단을 통계적 근거로 대체합니다.

**트리거 조건**: 사용자가 2개 이상 그룹(예: 개선 전 vs 개선 후, 또는 A방법 vs B방법)의 수치형 데이터를 업로드하고 "개선 결과 검증" 또는 이에 상응하는 목적을 선택했을 때.

## 2. 입력 요구사항

| 항목 | 필수 여부 | 설명 |
|---|---|---|
| 그룹 식별자 | 필수 | 2개 이상 그룹(예: before/after). 그룹 수는 자동 감지. |
| 측정값(수치형) | 필수 | CTQ 또는 기타 연속형 공정변수 1개 열. |
| 쌍(pair) 식별자 | 선택 | 동일 대상(동일 부품/동일 설비)을 전후로 측정한 경우 표시 — paired 검정 분기에 사용. |
| 측정 순서/타임스탬프 | 선택이지만 **강력 권장** | 시간순 연속 수집 여부 판단(자기상관 체크, 아래 Step 3)에 필요. 없으면 자기상관 체크를 건너뛰고 그 사실을 결과에 명시. |

## 3. E2E 처리 흐름 (결정론적, 사용자 개입 없이 전부 자동 실행)

```
Step 0. 데이터 인식        → 그룹 수, n, paired 여부, 시계열 여부 판정
Step 1. 시각화             → 그룹별 히스토그램 + 박스플롯 자동 생성
Step 2. 정규성 검정         → 그룹별 Shapiro-Wilk (n<50) 또는 병기 안내
Step 3. 독립성(자기상관) 체크 → 시계열 정보 있으면 런차트+자기상관 경고 로직
Step 4. 검정방법 자동 선택   → 아래 결정표에 따라 자동 확정(사용자 선택 불필요)
Step 5. 검정 실행+효과크기   → 검정통계량, p-value, 신뢰구간, 효과크기 동시 산출
Step 6. 패키지 출력 조립     → 1~5 전체를 하나의 리포트로 묶어 사용자 요청 없이 제공
```

### Step 4 결정표 (NAV-REQ-01/02 반영 — 가정 확인이 검정 실행보다 항상 먼저)

| 그룹 수 | Paired? | 정규성(Shapiro-Wilk p) | 선택되는 검정 | 비고 |
|---|---|---|---|---|
| 2 | Yes | 양쪽 그룹 p≥0.05 | Paired t-test | |
| 2 | Yes | 어느 한쪽이라도 p<0.05 | Wilcoxon signed-rank | 비모수 |
| 2 | No | 무관 (등분산 검정 생략) | **Welch's t-test (기본값)** | NAV-REQ-02: 등분산 가정 분기를 두지 않고 항상 Welch's 사용 — CLM-22/24 근거(worst-case 시뮬레이션에서 Student's t 1종오류율 22.3% vs Welch's 5.6%) |
| 2 | No | 양쪽 그룹 n<10 & 정규성 위반 | Mann-Whitney U | 비모수, 소표본 |
| 3+ | — | 전 그룹 p≥0.05 | Welch's ANOVA(등분산 미가정 기본값) | 사후검정은 Games-Howell |
| 3+ | — | 어느 그룹이든 p<0.05 | Kruskal-Wallis | 사후검정은 Dunn's test |

**사용자에게는 이 표의 분기 로직이 "왜 이 검정을 선택했는지" 1줄 설명으로 함께 노출됩니다(예: "두 그룹의 분산이 다를 수 있어 더 안전한 Welch's t-test를 사용했습니다")** — NAV-REQ-01의 "순서 투명성" 요구사항 반영.

### Step 3 자기상관 체크 (NAV-REQ-04 반영)

측정 순서 정보가 있으면: 런차트(run chart)를 자동 생성하고, 연속된 측정값 간 시차상관(lag-1 autocorrelation)을 계산합니다. |r|≥0.5면 "이 데이터는 시간순으로 서서히 변하는 경향이 있어, 통계 검정 결과의 신뢰도가 낮아질 수 있습니다"라는 경고를 **검정 결과보다 먼저** 표시합니다(FND-10 시뮬레이션 근거: rho=0.5에서 1종오류율이 명목 5%→25.6%로 5배 상승).

### Step 5 효과크기

Welch's t-test 사용 시 등분산을 가정하지 않는 방식(Glass's delta 또는 등분산 비의존 대안)을 사용합니다(Review Pass 2 "놓쳤던 점3" 반영). 비모수 검정 사용 시 rank-biserial correlation을 사용합니다. **p-value 단독으로는 절대 표시하지 않으며 항상 효과크기와 함께 제시**합니다(CLM-02/03: p-value 단독 제시는 과잉·과소대응을 유발).

## 4. 해석 템플릿 라이브러리 (슬롯 기반, AI 없이 결정론적으로 채움)

SRC-133(템플릿 기반 NLG 연구, 이해도 96.5%·자연스러움 97.5% 달성)의 구조를 따라, **[분류 규칙] → [슬롯 값] → [템플릿 문장]** 3단 구조로 설계합니다.

**슬롯 정의**: `{검정명}`, `{p값}`, `{유의여부}`(유의/비유의), `{효과크기값}`, `{효과크기등급}`(작음/중간/큼 — Cohen 기준), `{방향}`(개선/악화/변화없음), `{자기상관경고}`(있음/없음)

**분류 규칙 → 템플릿 예시 (일부, 전체 조합은 GAP-09에서 확장 예정)**:

| 유의여부 | 효과크기등급 | 자기상관경고 | 템플릿 |
|---|---|---|---|
| 유의 | 큼 | 없음 | "{검정명} 결과, 개선 전후 차이는 통계적으로 유의하며(p={p값}) 효과크기도 큽니다({효과크기값}). 실제로 의미 있는 개선으로 판단됩니다." |
| 유의 | 중간 | 없음 | "{검정명} 결과, 개선 전후 차이는 통계적으로 유의합니다(p={p값}). 효과크기는 중간 수준({효과크기값})으로, 확실히 나아졌다고 볼 수는 있으나 아주 큰 변화는 아닙니다. 현장에서 체감되는 정도와 비교해 실질적 의미를 함께 판단하십시오." |
| 유의 | 작음 | 없음 | "통계적으로는 유의하지만(p={p값}) 효과크기는 작습니다({효과크기값}). 표본수가 많아 작은 차이도 유의하게 나온 것일 수 있으니, 현장에서 체감할 만한 차이인지 함께 확인하십시오." |
| 비유의 | — | 없음 | "이번 데이터에서는 개선 전후 차이가 통계적으로 확인되지 않았습니다(p={p값}). 차이가 없다는 뜻이 아니라, 이번 표본으로는 확인하지 못했다는 뜻입니다. 표본을 늘리거나 조건을 통제해 재확인을 권장합니다." |
| — | — | **있음** | "⚠ 이 데이터는 시간순으로 서서히 변하는 경향이 발견되어, 위 검정 결과의 신뢰도가 낮아질 수 있습니다. 결과를 참고용으로만 활용하고, 가능하면 무작위 순서로 재측정한 데이터로 재확인하십시오." (다른 모든 템플릿보다 **우선 표시**) |
| (템플릿 매칭 실패 시 기본값) | | | "이 조합에 대한 표준 해석 문구가 아직 준비되지 않았습니다. 수치 결과({검정명}, p={p값}, 효과크기={효과크기값})를 직접 확인하시거나 통계 담당자에게 문의하십시오." — **모든 패키지 필수 포함(성공기준 "경고" 항목 반영)** |

**[2026-09-10 추가, GAP-09 전수화]** 위 표는 유의여부(2) × 효과크기등급(3: 큼/중간/작음, 비유의일 때는 해당없음) 조합을 전부 커버합니다 — 비유의 행은 효과크기와 무관하게 하나의 템플릿으로 처리(비유의 상태에서는 효과크기 크기를 해석에 활용하지 않는 것이 통계적으로 안전하므로 의도된 설계). 자기상관경고는 핵심 분류와 독립적으로 존재 여부만으로 항상 최우선 표시되는 **접두 경고(prefix warning)**이며, 핵심 분류(유의여부×효과크기)와는 별개 차원이므로 서로 배타적이지 않고 함께 표시될 수 있습니다(예: "유의+중간" 템플릿 뒤에 자기상관경고가 이어 붙는 형태). 이 접두 경고 vs 배타적 핵심분류 구조는 M-INTERP-ASSEMBLE의 공통 조립 규칙이며, `Analysis_Module_Library_and_Composition_Rules.md` §2.7에 근거로 명시됩니다.

## 5. PRISM 연동 관련 미확정 사항 (GAP-08)

이 명세는 PRISM의 기술 스택·데이터 스키마·API를 모르는 상태에서 작성된 **기능 명세**입니다. 아래는 Ian의 확인이 필요한 항목입니다: (1) PRISM에 이미 저장된 CTQ 데이터를 이 패키지가 직접 조회할 수 있는지, 아니면 사용자가 별도 업로드해야 하는지. (2) Add-on의 실행 위치(PRISM 내장 모듈 / 별도 서비스+연동) 및 그에 따른 기술스택 제약. (3) PRISM의 기존 UI/UX 패턴(메뉴 구조, 리포트 양식)과의 일관성 요구사항.

## 6. 다른 패키지에 적용할 재사용 패턴

이 문서의 구조(목적/트리거 → 입력요구사항 → E2E 흐름 → 결정표 → 해석템플릿 → 안전장치 → PRISM 연동 미확정사항)를 그대로 따라, 다음 패키지들을 순차 작성할 것을 제안합니다: **원인분석 패키지**(CASE-005 대응 — 후보원인 그룹간 t-test/ANOVA 자동 실행+파레토), **핵심요인분석 패키지**(CASE-006 대응 — 다중회귀 변수중요도), **MSA 패키지**(CASE-004 대응 — Gauge R&R 자동계산+%R&R 판정), **유지관리 패키지**(CASE-008 대응 — 개선 후 자동 추적 알림+간이 관리도).
